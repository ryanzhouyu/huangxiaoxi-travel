黄小西换装体验画板研究

研究日期：2026年10月19日。原始来源：RunningHub 只读画板。本次范围为素材归档、功能与视觉研判，以及下一轮流程讨论的准备。

后续确认：换装主体为黄晓西数字伙伴，一期聚焦打卡、收集、换装与回忆，宠物后置；本周先做可部署测试体验版，并演示购买次数与模拟支付。当前业务规则见 一期产品规则与业务流程，本文保留画板研究时的观察与建议。

建议把下一阶段的产品主线定为：游客在真实旅途中，与自己的智能伙伴共同经历地点、获得当地装扮，并留下可分享、可制作成实物的个人旅行纪念。 现有画板已经有完整度较高的换装收集界面、地图导览和回忆地图；最需要补齐的是“真实经历如何成为一条记忆，并进入最终纪念品”的连续过程。

这条主线是根据本次口述目标提出的产品建议，尚未作为已确认规则。原稿中的抽奖、同行人和宠物系统保留为研究对象，首期范围留待下一轮确定。

三 根据原稿重建的体验流程

进入与收集

启动 → 创建昵称和形象 → 引导 → 陪伴首页 → 区域选择 → 景区选择 → 景区导览 → 点位详情 → 到场扫码 → 获得抽奖机会 → 查看抽取结果 → 放入衣橱或背包 → 更换服装、动作、背景。

这条链路最完整，但首次装扮的获得、第一次打卡的成功反馈和第一次产出纪念图片之间，还缺少明确的连贯设计。例如：游客获得头饰后，是否立即预览穿戴效果，是否自动留下一张当时当地的合影，原稿没有串清。

商家支线

点位详情的动作彩蛋或地图商家入口 → 商家列表与详情 → 导航到店 → 扫描商家码 → 解锁动作或获得券 → 回到背包搭配。

原稿表现了“到店扫码”，本次口述还增加了促销与体验活动。后续应将“到达商家”“完成消费”“参加活动”分成不同任务条件，分别说明游客需要做什么以及能得到什么。

同行与亲密度支线

邀请同行人 → 对方确认 → 关系标签 → 赠送虚拟小吃 → 亲密度增长 → 领取宝箱 → 获得券或套装。景区回忆页另有单人、情侣、同行人展示方向。

这里已经形成社交养成机制，但“共同走过一个景点”怎样产生共同记忆，没有与邀请、打卡、合影权限直接衔接。可以优先讨论同游价值，再决定是否需要复杂送礼系统。

宠物支线

满足领养条件 → 免费随机孵化或付费指定 → 等待或立即孵化 → 命名 → 换装／安排旅行 → 倒计时或加速 → 返回结算 → 获得虚拟收获、旅行照片。

画板文字明确写了亲密度达到 10 可领养、免费等待 8 小时、三种随机形象；051 和 053 的示例界面显示 9.9 元指定或立即孵化。以上是原稿规则，并非本次建议保留的定价或上线规则。

回忆支线

打卡与收获事件 → 景区回忆地图 → 省域旅程汇总 → 生成图片或视频 → 分享。

这条链路的结果页已有方向，事件采集与编辑环节仍需补齐。044 中的 2025 年日期和 006 中的 2024 年日期是示例时间，不能当成真实用户旅行记录。

四 视觉风格与样式

核心气质

整体偏向贵州山水与地方文化元素结合的 Q 版旅行幻想世界。建筑、峡谷、瀑布、花草、灯笼和民族服饰共同构成场景。角色普遍采用大头、大眼、小身体的可爱比例，服装、头饰和配件承载收集价值；背景拥有丰富层次和柔光。

它适合传达陪伴感、收集欲和旅行纪念感。用户提到《奇迹暖暖》是参考来源；从本画板能确认的是换装、部件收集、套装图鉴与奖励演出的借鉴方向，不能仅凭图片判断具体实现或素材来源。

手机端的阅读风险

以卡池 012 为例，原图宽 941 px，若整张压到约 390 CSS px，显示比例约为 41%；原图 24 px 的文字仅相当于约 10 CSS px。底部任务奖励、概率说明和按钮辅助文案会非常吃力。044 的省域回忆页同时容纳 8 个地点、统计与分享入口，更适合重排为可滚动内容或单独导出长图。

后续应把这些图片当作视觉与信息参考，重新制作真实组件；景点图片、二维码、文字和价格不能直接嵌在整张背景图里充当可用界面。分享海报的二维码应由系统生成真实目标码，并经过实际扫描验证。

纪实素材的使用

画板里有 ChatGPT Image 文件名，也有明显的概念插画。建筑外观、商品图、民族服装、店铺名称和介绍不能仅凭生成图定为事实。正式产品需建立“真实景点和商家素材”“原创幻想装扮”“游客真实照片”的来源标记，并核对地方文化表达。

五 落地前需要解决的产品问题

角色是谁

目前存在黄小西品牌角色、游客创建的角色、同行人的角色，以及宠物四个主体。需要确定游客是在“拥有自己的黄小西伙伴”，还是“用一个虚拟形象代表自己”，黄小西在其中是向导还是被换装的对象。这会影响昵称、第一人称对白、对话记忆、合影和实体纪念品的主角。

建议下一轮优先确认这一点，再确定首页结构和创建流程。

一趟旅程如何成立

原稿有省域回忆和景区回忆，但还没有清楚定义“这一趟”。建议将一次贵州出游作为旅程，其中可以有多个景区和日期；一次打卡作为旅程内事件。省、市、景区、景点和商家分别建关系，不能把导航目的地、活动核验点和回忆节点混为一个对象。

旅程应支持游客提前结束、跨天继续、临时改路线及只去一个点的情况。只有一次有效体验，也应该能留下完整的小纪念。

打卡怎样成为一条可追溯的记忆

建议每次有效体验保存：所属旅程、地点、时间、完成的活动、获赠的装扮或动作、当时穿搭、照片来源，以及游客确认的心情或短句。共同经历另需保存同行确认状态。

历史记录保存当时搭配的版本；后来换衣服不应悄悄改写旧合影。允许游客重新演绎纪念图，但应作为新作品保留来源。AI 可以润色回忆文字，不能凭空增加游客没有做过的活动或共同到场经历。

每次到场都应得到什么

原稿以抽奖券和随机部件为主。建议优先验证“到场即得一个可立即使用的当地纪念”，例如基础装扮、标志配件、动作或场景。稀有奖励可作为额外惊喜，避免游客完成短途游玩后仍没有可用的完整形象。

012 写明不重复获取；若继续使用这套规则，需定义剩余奖品不足五件、奖池抽空、账号间差异、券剩余与退款等边界。031 示意五连抽 12 元、035 示意单抽 3 元，仅为原稿示例价格。是否付费抽取及其规则另行决定。

商家活动的价值和核验

每个活动都应明确展示参与条件、地点、耗时、消费要求、奖励、有效期和领取方式。游客不应到店后才发现需要消费；商家需能验证真实参与、避免重复发放，并处理奖励缺货或活动停止。

“点开分享”与“完成外部平台发布”是不同事件。原稿的分享送券需要根据实际接入能力决定核验方式，不能默认能够读取所有社交平台的发布结果。

动作与服装如何组合

当前动作页有表情姿势网格和配置槽，商家详情有 GIF 示例概念。需先明确首期“动作”是静态合影姿势、短循环动画，还是实时角色动作。

若逐组合出图，体型、服装、动作、场景的组合量会相乘。建议先选一个稳定角色母版与有限姿势，验证衣服遮挡、手持物、头饰、场景透视和导出质量，再决定使用 2D 分层、3D 或受控生成。原图本身不能证明已经具备这些技术能力。

纪念图片与实体商品如何衔接

建议以“记忆事件 → 作品 → 商品”的关系设计。作品可组合角色、真实或授权景点背景、路线和时间；先让游客编辑、预览和保存，再选择明信片、冰箱贴或画册。

数字服饰、虚拟小吃、实体奖品、兑换券和定制商品需要分别定义。实际下单前必须确定尺寸、分辨率、裁切安全区、文字、工艺、库存、价格和交付方式。首个实体品类应根据供应商条件选择，不能仅凭原稿商品图承诺生产。

宠物与真实旅行的关系

宠物派遣能提供离开景区后的持续互动，但 8 小时等待和道具加速会增加首日体验成本。更关键的是，宠物虚拟旅行获得的“地点照片”不能让游客或分享接收者误以为是真实到访。

建议首期让宠物成为可选陪伴或合影元素；独立派遣、孵化收费、复杂消耗和多宠养成放到后续验证。这是阶段建议，不是删除既有设计的决定。

同行人的信息与回忆权限

真实同行、情侣关系和普通好友的需求不同。建议先覆盖同游邀请、共同打卡、合影确认与分享权限，随后再评估亲密度和赠礼系统。解除关系后，历史合影如何保留、能否继续对外展示，需要提前约定。

六 供下一轮讨论的最小闭环

建议先用一个景区内的一条短路线验证端到端体验。以下数量是试点讨论起点，不是已确认需求：3 至 5 个打卡点、1 至 2 个合作商家、1 套可直接使用的基础装扮、少量可组合奖励、若干稳定姿势、1 个旅程回忆模板，以及供应链可支持的 1 个实体纪念品。

建议流程：进入黄小西 → 快速获得伙伴和基础形象 → 看到附近可获得的体验与奖励 → 到达一个点并完成核验 → 当场获得可用装扮或动作 → 立即看到穿戴与合影效果 → 自动记下一条可编辑的旅行记忆 → 继续游玩 → 结束时形成回忆地图和分享作品 → 自愿选择实体纪念品。

游客阶段必须回答的问题样板应展示的结果
刚进入我是谁，伙伴是谁，现在有什么可玩无需先理解整套系统就能得到可用形象和下一站
到达景点怎样确认我来过，能得到什么条件清楚；成功与失败反馈明确；重复操作不多发奖励
获得奖励奖励有什么变化，能不能马上用即时预览、穿戴或姿势应用；保存后跨页面一致
形成记忆系统记住了什么，我能不能修改正确地点与时间、当时穿搭、图片和短句；游客可编辑
旅程结束我能带走什么至少一张好看的作品和可回看的旅程；分享与购买分开选择
选择实物做出来是什么样，怎么交付清晰的规格和图稿确认；接入后可实际完成订单与领取／邮寄

建议用于试点验收的重点是：首次有效奖励完成时间、第一次作品产出率、打卡和发奖成功率、记忆内容准确性、导出清晰度，以及游客是否愿意保存或分享。数值阈值需结合试点场地和用户测试约定。

七 后续文档与数据边界

产品流程明确后，再将确认内容写入 PRD 和项目约定。建议先建立以下对象关系，避免界面推进后才发现数据无法支持回忆：

对象保存的核心内容
游客与伙伴账号、伙伴身份、角色母版、昵称、当前搭配
旅程起止、范围、包含的景区、状态、同行关系
地点与活动地理层级、到访条件、任务条件、奖励配置、开放状态
核验与奖励参与凭证、核验结果、唯一领取记录、奖励来源与库存
角色资产部件、套装、姿势、场景、适配范围、持有状态
记忆事件真实时间地点、体验、穿搭版本、照片来源、用户文字、可见范围
纪念作品采用的记忆、模板、合成版本、输出文件、用户确认
实体订单作品版本、商品规格、价格、图稿确认、制作与交付状态

这里是一组流程讨论需要的数据边界，不是最终数据库设计。

八 下一轮优先确认的事项

  1. 身份模型：换装的是游客自己的分身，还是属于游客的黄小西伙伴？两者需要如何共存？
  2. 首发场景：先在哪个景区和哪类游客中验证？单人、情侣、亲子或朋友同行，哪一种是主场景？
  3. 首次价值：游客在第一次到达后，最希望马上看到的是新装扮、与景点合影，还是一条旅行记忆？
  4. 资产方式：对人物一致性、自由换装和动作连续性的要求有多高？先用稳定静态作品验证，还是已有角色引擎和可用素材？
  5. 试点交付：目前能接入哪些地图、打卡凭证、商家活动及文创供应商？第一种可实际交付的纪念品是什么？

原稿其他内容均已归档，可以在主线确认后按需要恢复或深化。下一轮建议从“一位游客进入一个具体景区的一天”开始，逐步补全每一步的触发、操作、反馈、奖励、记录和异常处理。

> 历史记录：保留原日期、原路径和当时结果，供回溯与回归；文中的“下一步／本轮”属于该阶段。当前状态以 [HANDOFF](../HANDOFF.md) 为准，新的整理结果见[项目复盘](项目复盘与资料整理记录.md)。

这轮调整针对上一版的核心问题：页面虽然可以完成业务操作，但布局仍以标题、说明卡、列表和下一步按钮为中心，伙伴和场景只是功能页面里的内容块。当前改用伙伴所在的场景承载入口，地图承载探索，试衣界面承载搭配，旅行手账承载回忆。人物和背景仍为代码示意，正式美术素材方案继续后置。

新版入口：[黔山纪游](../design/index.html?v=3#partner)。本机地址为 `http://127.0.0.1:8765/design/index.html?v=3#partner`。已有浏览器进度继续使用，当前账号不需要重新创建。v0.2 已保存在 design/archive/v0.2，不覆盖历史版本。

## 页面如何承载游玩

首页提供“伙伴在这里”的状态，进入后直接看见人物与周围风景。点人物或对话框会得到回应；回应不发奖、不积累亲密度，也不代替后续完整智能体对话能力。背包是去试穿的地方，地图是去逛的地方，回忆是保存经历的地方，首页不再排列业务步骤。

主要场景入口调整为伙伴、游玩、回忆三个。衣橱从伙伴旁的背包、抽取结果或纪念图制作进入，作为独立试衣界面，不再在底部重复列入口。保存或取消返回来源；未保存搭配仍执行保存、放弃、继续编辑的保护。

地图上的路径和地形为示意，不构成必做路线或真实导航。点标记先了解地点、奖励和参与条件，核验成功才记录足迹、发放首次次数和解锁卡池。已来过的地点显示已留足迹，领奖资格与到访记录仍分别处理。

抽取有短暂开启反馈和独立获得展示，奖品在展示前已完成本地入库，不依赖是否点“穿上看看”。展示结束可试穿、保存或先收好。概率、余额、未解锁和收齐状态仍明示，不因表现方式改变规则。

回忆依据已有测试到访产生。手账中的节点可以打开经历，也可以单条或多条制作图片。图片延续同一套场景与伙伴示意，加入标题、地点时间和足迹线；后续换装只用于新作品，不改写原作品。

## 本轮检查

| 检查层面 | 判定方法 |
| --- | --- |
| 场景结构 | 首页不含功能说明卡、统计卡和业务步骤；角色、入口及对话框同屏；地图标记直接进入对应地点 |
| 换装结构 | 人物、分类和可见部件同屏；只让部件柜滚动；保存返回保持来源上下文 |
| 可操作性 | 360×640、390×844、430×932 手机及1440×1000桌面检查；关键按钮中心不被覆盖；首页、地图及衣橱无额外整页滚动 |
| 收集反馈 | 开启后展示实际获得的部件，并提供试穿；库存、扣次、解锁、去重仍正确 |
| 视觉复核 | 直接查看首页、地图、衣橱、图鉴、卡池、获得结果、手账、入口、初始化、小屏和桌面截图；修正人物偏小、部件文字过细和标签拥挤 |
| 业务回归 | 从新账号实际领装、打卡、抽取、试穿、制作和下载 PNG，覆盖取消、失败、重复及恢复 |

业务回归记录见 [verification.json](../design/verification.json)，游玩布局检查见 [game-verification.json](../design/game-verification.json)。自动断言检查结构与交互条件，不能证明审美或游玩感已经达到用户预期，最终方向以实际体验反馈为准。

## 当前能力边界

本轮改动没有接入云端账号、真实支付、真实位置核验或店员系统；两个演示账号继续保存在当前浏览器。场景、人物和部件均为代码绘制的布局示意，不使用整张原画板截图充当可交互页面。新的 PNG 保留演示作品标记，历史作品保持原样。

后续应先依据这套布局确认伙伴、探索、换装和收集的表达是否合适，再逐页精修及替换正式素材；不再用“功能已跑通”代替界面体验的确认。

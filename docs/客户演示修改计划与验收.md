# 黄晓西客户演示修改计划与验收

计划日期：2026-11-05。目标：2026-11-06 上午，电脑投屏向客户／业务方连续演示。状态：待执行的实施方案；本次只编制计划，没有修改产品代码。基线为 `main` 的 `4d2c933`。

交付目标是一个入口、一份连续进度、一套一致的伙伴搭配，以及可以实际保存的纪念图片。观众能够看懂“伙伴陪伴—实地游玩—收集换装—留下回忆”的因果关系，演示者无需修改后台数据、切换独立设计状态或跳到另一套原型才能完成主线。

## 一 交付范围和通过条件

### 必须完成的结果

1. 新演示身份从零开始，没有预置到访、解锁、余额或作品；全部初始装扮免费可用。
2. 线上领取只增加拥有物，试穿保存后才改变正式搭配；领取不产生到访。
3. 四个测试地点各有正确详情、核验、奖励和关联卡池。有效到访才记录经历、发次数、解锁；错误码不成功。
4. 抽取实际扣次、入库，跨池排除已拥有资产。首页、卡池、图鉴和次数账本显示同一份数据。
5. 试穿、保存和放弃有明确区别。保存后的伙伴在首页、衣橱和新纪念图中一致，并且能看出搭配变化。
6. 商家到店与体验核验分别产生记录和首次奖励；购买只增加景区通用次数，不解锁卡池。
7. 有有效到访即可制作图片；选中的经历、标题、模板和搭配实际进入 PNG。旧作品保持固定，下载文件能够打开。
8. 电脑投屏首屏能看到主要操作和三个主场景入口；演示中不出现设计目录、验收工具及无效入口。
9. 新身份完整主线、回访恢复、再次开场各彩排一次，三次均没有阻断或业务矛盾。历史测试通过不能替代这三次彩排。

### 本轮能力边界

| 能力 | 本轮实现要求 | 现场表述 |
| --- | --- | --- |
| 身份与进度 | 独立的本机演示身份，刷新与回访可恢复 | 演示进度保存在本机；正式账号与云同步后续接入 |
| 到访 | 测试点位码真实校验内容；定位、活动确认明确模拟 | 本次用测试码模拟现场到访，不证明真实到场 |
| 次数购买 | 完整模拟订单、成功／失败／取消及到账 | 模拟支付，不发送真实交易 |
| 伙伴表现 | 有限静态部件／表情／姿势变化，三端同源 | 演示素材，正式角色和动画技术后续确定 |
| 纪念作品 | 实际合成、保存、下载 PNG | 可以保存图片后在社交应用发布 |
| 分享 | 支持则调用系统分享，不支持则提供图片下载 | 不宣称已经发到微信／朋友圈 |

本轮不引入真实短信、微信授权、支付、定位服务、后台、生产角色引擎、动画、宠物、视频或实体下单。不增加稀有度、保底、次数有效期等未确认规则。

## 二 实施方式及代码边界

建议新增独立的 `design/demo/` 连续演示入口。保留 `design/hifi/` 作为原视觉评审稿、`design/index.html` 作为已有业务原型；正式演示只使用新入口。这是为短期演示隔离变更的方案，不是复制第三套完整业务系统。

- **规则复用**：调用现有 `design/store.mjs` 和 `design/data.mjs`，不在页面另写发奖、扣次、订单到账与排重规则。现有业务测试继续保护规则。
- **视觉复用**：沿用高保真的场景、纸面、插画与布局；把需要动态数据的页面按职责提取／适配。不能继续用字符串替换云山／花溪名称的方法处理地点和卡池。
- **状态隔离**：演示存储适配器将业务存储接口映射到独立命名空间，例如 `hxx.demo.v1`。不改写原型的 `hxx.interactive.v2`，不自动导入、清除用户旧进度。异常读取时保护原值。
- **作品同源**：伙伴、试穿和 PNG 都消费同一 `look` 与渲染适配器。新作品固定图片及来源快照，编辑草稿与旧作品分开。
- **演示控制隔离**：复位、样例码提示、检查结果放在独立演示准备页，正常游客页面仅保留必要的模拟标识。

下列为建议新增入口，实际实施时可按清楚职责合并小文件，不机械追求目录数量。

## 三 按依赖执行的修改任务

每项完成后记录实际文件、结果和证据；以下状态全部为待执行。任务验收未通过时不得把它标成“已完成”，也不得用讲解替代必要结果。

### D00 固定版本和演示数据口径

- 检查工作区，保留用户改动；建立建议分支 `codex/client-demo-20261106`，按可回退目标组织后续提交。
- 将本次复现问题整理成用例：地点串错、虚假成功、重复奖品、余额不动、套餐错额、旧作品被改等，作为最终回归输入。
- 固定本轮一个测试景区、四点位、一活动、两池和现有套餐配置；整理 ID 与页面对应表。
- 验收：原型和高保真入口仍可访问；新增演示入口不会覆盖旧存档；各资产、地点、卡池引用有效。

### D01 先做角色与 PNG 样板

这是本轮最大风险，必须在铺开全部页面前验证。

- 盘点现有素材：高保真 `companion.png` 是单张概念图，不能直接逐件换装；现有 `stageFigure(look)` 是可替换 SVG 示意人物。
- 首选用现有可替换 SVG 能力制作独立的有限演示渲染器，改善与高保真场景的配色、轮廓和比例；保留固定脸部结构。演示中统一使用该角色，不能在首页展示精细概念人物、进入衣橱后突然变成另一人。
- 先只验证两组差异清楚的搭配、一种静态表情变化和一种静态姿势变化；再核对两个卡池所有可抽资产均有有效显示映射。未做动画，不显示动画已完成的引导。
- 在伙伴首页、衣橱和一张下载 PNG 中使用完全相同的搭配；背景选择必须体现在纪念图，而非只改页签高亮。地图仍是测试示意，不冒充真实景点背景或导航。
- 验收：三端逐图对照；脸部身份一致，服饰／表情／姿势变化可辨，部件无明显漂浮遮脸，PNG 无缺图。检查 390×844 和投屏尺寸。
- **停止条件**：若样板显著破坏已认可视觉，先提交三端对比确定取舍，不默认切回粗糙人物，也不假装概念 PNG 已支持换装。样板未过，不能承诺完整高保真换装演示就绪。

### D02 演示身份和状态管理

依赖 D00，可在 D01 样板明确前先准备接口。

- 新入口采用明确的“使用演示身份进入”，不假装发送短信；正式登录／绑定方案仍留在设计稿，本轮不接真实账号。
- 新身份初始余额 0、到访 0、卡池未解锁、作品为空；初始化授予全部初始装扮，首次选择只决定默认搭配。
- 用存储适配器调用现有事务操作。操作成功后才更新页面；写入失败保持原数据、显示可重试反馈。
- 建立独立的编辑草稿和制作草稿，保存选中资产、来源路由、标题、模板、经历 ID；跨页／刷新按状态恢复。
- 验收：初始化、退出、回访、刷新都正确；两个演示身份互不混用；原型旧键的内容逐字节不变；存储不可用时不显示“已保存”。

### D03 投屏入口和导航骨架

依赖 D02；先接伙伴、景区、衣橱、回忆四个骨架，后续填真实状态。

- 新入口隐藏评审目录、状态按钮和说明侧栏，保留伙伴／游玩／回忆三个主场景。
- 登录、初始化不出现游玩导航；详情页有来源返回，编辑页有保存／取消。路由携带 `sceneId`、`pointId`、`poolId`、`outfitId`、`orderId`、`workId` 等必要 ID。
- 电脑采用适合投屏的布局：让人物、主要操作和底部导航同屏，长列表独立滚动；不把全部文字缩到无法阅读。
- 验收：1280×720、1440×900、1920×1080 均能完成投屏主线；另核对项目参考尺寸 360×640、390×844、430×932、1440×1000。未知 ID 显示可返回的错误页，不默认套用望山台或云山卡池。

### D04 初始化 线上领装和试穿

依赖 D01—D03。

- 三种初始搭配均从配置读取，对应真实 `look`；确认后首页显示所选搭配。
- 景区见面礼按账号只领取一次；领取前后分别显示可领取／已领取，不反复弹“新获得”。
- 领取成功只增加库存；“穿上看看”创建试穿草稿，保存后改变正式搭配，取消恢复原搭配并回到景区。
- 验收：领装前后余额、到访、解锁均不变；重复领取不增加资产；未保存时首页仍是旧搭配；保存／放弃均回到原景区。

### D05 地点 商家和有效核验

依赖 D02—D04。

- 从固定配置渲染四点位的名称、类别、奖励、领奖资格和关联池。地图、地点列表、来源入口进入同一个 ID 的详情。
- 核验页接收完整地点上下文；测试码使用当前配置：入口 `HXX-GATE-2026`、望山台 `HXX-RIDGE-2026`、花溪 `HXX-BROOK-2026`、商家 `HXX-SHOP-2026`。
- 输入错误或其他地点的码时拒绝操作。成功后同一事务记录经历、首次奖励、流水和关联解锁；弹层显示本次实际结果。
- 商家到店 +1，与完成手作 +2 分开；手作模拟失败无变化，成功只发一次，并显示活动来源。
- 初次到访只有本地点经历；重复到访按现有防重规则处理，既不重复发首次奖，也不伪造新奖励。
- 验收：逐点点击和核验；入口／望山台解云山，花溪／商家解花溪。至少覆盖错误码、串点码、重复点击、再次进入、模拟失败及商家返回。没有有效到访时仍不能生成作品。

### D06 抽取 入库和跨页面查询

依赖 D05。

- 卡池读真实拥有物、余额、解锁和 `eligible` 候选集，显示剩余数量与等概率；结果取自实际 `draw` 返回的资产 ID。
- 一次抽取消耗一次、只发一个新资产，完成入库后再显示结果。连点期间锁定提交；相同请求重试不再次扣次。
- “再抽一次”重新读取余额和候选集；抽到表情、姿势、背景时均提供准确分类的试用入口。
- 图鉴与套装详情按真实 `outfitId` 显示部件；同一资产跨池拥有状态共用。获得后不再显示“去收集”。
- 验收：抽取前后核对余额、流水、库存和结果；退出重进／刷新数据一致；连续抽取不重复；锁池不可抽，余额不足不扣次，收齐不扣次且不继续抽取。

实施 D05—D07 时先接通“山门入口→有效核验→云山抽取→试穿保存→回到原池”的最小样板，再推广到其他点位、花溪与活动。不能先把全部页面改完才发现跨页调用不成立。

### D07 衣橱草稿 保存和来源返回

依赖 D01、D04、D06。

- 衣橱从正式搭配复制草稿，选择已拥有资产后实时渲染；未拥有资产只展示来源，不可直接穿戴。
- 获取结果进入衣橱时定位并试穿刚获得资产，免费套装试穿定位对应套装；不要默认回到任意头饰。
- 所有离开方式经过统一草稿保护，包括顶部返回、浏览器返回和主场景切换。未改动直接返回；有改动可保存、放弃或继续。
- 保存调用规则层成功后更新首页和新作品输入；取消不改正式搭配。返回携带原卡池／景区／制作参数。
- 验收：从首页、见面礼、两个池的获得结果、制作页分别进入并返回；制作标题／经历不丢。保存后刷新仍一致；故障重试不丢草稿，不误改另一个账号。

### D08 套餐 订单和到账

依赖 D02、D06，可在 D07 后作为主线支线完成。

- 套餐、确认页、模拟支付弹层、成功页、账本和订单详情都读取同一个订单对象，不在弹层写死 5 次／¥4。
- 1／5／10 次分别映射当前配置 ¥1／¥4／¥7；选择套餐后新建待付订单，刷新后仍能按 `orderId` 找到该订单。
- 成功只到账一次；失败／取消不发次。保留来源池，不能从花溪购买后强制返回云山。订单列表点已成功订单不会变成新的待付订单。
- 验收：三个套餐逐项对照；成功／取消／失败三终态、刷新及重复回调；有余额的锁定池仍锁定；首页、池、账本余额相同。

### D09 手账 纪念图和作品下载

依赖 D01、D05—D07。

- 手账仅渲染本身份实际记录，日期用实际到访时间；地点到访与活动完成分别有名称和方式。没有“必须完成路线”或“结束旅程”。
- 制作草稿保存具体经历 ID，不只存数量。重开选择保留勾选；选 0 条不可生成，选 1 条不出现未选地点。
- 纪念图使用当前保存搭配、所选经历、标题和模板；单页与长图在排版／尺寸上有实际差异。示意地点背景由稳定配置映射，不能把所有地点默认为同一张真实景点照片。
- 合成异步防重；更改标题／搭配／经历后使旧预览失效；合成失败保留输入并可重试，离页后的旧结果不能覆盖新页面。
- 保存作品固定 PNG、标题、搭配、时间和经历快照，以 `workId` 查询。编辑另一作品不改变旧作品，不自动覆盖历史图。
- 下载真实 PNG，打开核对文字、日期、人物和经历；分享不支持时引导保存，不显示“分享成功”。长标题合理换行，不裁断。
- 验收：分别生成 1 条与 3 条经历、两种模板；制作中换装返回；作品 A 保存后制作 B，再打开 A 核对标题和图片哈希；合成／存储失败恢复；文件下载并用独立图片查看器打开。

### D10 演示准备 复位和运行预检

依赖 D02—D09。

- 独立演示准备页列出入口、版本、测试码、素材加载和存储可用性。只面向演示者，不占用游客首页。
- 提供仅作用于演示命名空间的复位，显示影响范围并确认；不执行 `localStorage.clear()`。旧演示存档可单独备份，备份文件不提交 Git。
- 新开场存档从零开始；备用回访存档必须由正常操作产生，并标明实际状态，不注入隐藏奖励或固定抽取结果。
- 全部运行资源本地引用；服务绑定和演示入口一致。验证断开外网仍能加载、操作、合成、下载。检查电脑电源、分辨率、缩放、通知及投屏实际可读性。
- 验收：复位后初始条件准确、其他存档不变；关闭页面再打开能恢复；服务重启后入口可用；准备页无未通过预检。若换电脑，必须重新跑预检与主线，不能仅复制聊天。

### D11 两轮审查及实际彩排

依赖 D00—D10。

- 第一轮审查业务结果与失败恢复，按下一节验收表逐项验证；测试使用独立上下文。
- 第二轮从客户视角找误解：同一对象跨页名称是否一致，按钮是否承诺未实现能力，奖励来源是否清楚，是否出现死路和技术弹窗，图片是否体现选择。
- 在 1280×720 和实际投屏尺寸看图并实际操作，不仅检查 DOM；确认背景、人物和文本没有明显退步。
- 执行三次彩排：① 新身份完整主线；② 同身份回访、刷新、旧作品查看；③ 复位后再次完整演示。抽取随机结果不同也必须完成，不依赖指定奖品。

### 可以缩减的内容

- 不演示正式短信、微信绑定、账号恢复、安全设置等设计支线；入口写明本机演示身份。
- 不扩大角色美术数量、动效或更多纪念模板；保留已有静态槽位及可验证样板。
- 减少投屏中展开的非主线支线，未接通入口隐藏或明确置为说明，不能留下假成功按钮。
- 订单若未完成一致性验收，可从现场主讲移为后续补充；交付说明明确缺失，不能声称已覆盖全部主要功能。

### 不能缩减的内容

地点与奖励准确、有效到访前置、次数扣发一致、跨池排重、换装可辨与三端一致、作品固定及实际 PNG、完整来源返回和至少一次实际投屏彩排。不能用预置足迹／固定中奖／硬编码到账伪装完整流程。

若新入口主线仍未达到放行条件，备用方案是“高保真概念展示＋明确切到已验证业务原型”，并使用真实导出图及本地录制的完整操作作为补充。它能保障会议继续，但不算完成单入口高保真闭环目标。录屏与备用存档必须来自正常操作，不掩盖未实现能力。

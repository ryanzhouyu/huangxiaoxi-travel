# 黄晓西入口与数字伙伴子流程

更新日期：2026-10-19。状态：入口业务补充。卡片 01 至 03 已确认；当前操作以[交互规格](完整体验与验收标准.md)为准，素材接口见[渲染规范](素材与渲染接口规范.md)。本文件不单独维护另一套页面状态。

本周制作独立手机网页，以演示账号承载进度，不接现有黄晓西系统。黄晓西为游客拥有的固定脸部身份数字伙伴，游客不上传本人照片；初始模板用于选择默认装扮。

## 已确认规则

| 项目 | 规则 |
| --- | --- |
| 运行方式 | 可独立部署的手机网页。 |
| 用户识别 | 演示账号，验证进度保存，不接现有账号系统。 |
| 初始装扮 | 全部初始装扮免费可用，首次选择只决定默认搭配。 |
| 身份一致性 | 脸部身份固定，发型、妆容、服饰等可按资产规则替换。 |
| 素材基线 | 当前主要为画板图片，先使用简化的可替换素材，视觉精细度后续完善。 |

## 操作与处理方案

| 场景 | 游客操作 | 系统处理与保存 |
| --- | --- | --- |
| 首次进入 | 使用一个演示账号进入，查看并选择初始模板，确认。 | 为该账号建立伙伴，发放全部免费初始资产；保存所选模板对应搭配。 |
| 确认后 | 查看已穿戴形象，进入景区体验。 | 首页、衣橱与纪念图使用同一份已保存搭配定义。 |
| 回访 | 使用同一演示账号进入。 | 恢复已有伙伴、装扮、余额、打卡与回忆，不重复发初始资产或要求重新选择。 |
| 更换初始搭配 | 在衣橱使用已有初始资产或模板。 | 改变穿戴状态，保留已获得的其他资产与记录。 |
| 现场扫码首次进入 | 完成必要的伙伴建立后继续原点位操作。 | 当前实施方案保留完整扫码目标，不强制先浏览景区或领取套装；这是已采用的交互，不新增业务门槛。 |

确认保存失败时不提示创建成功；重试返回已经创建的伙伴或继续完成保存，不生成重复伙伴。演示账号的选择入口、会话和存储方式由实施方案决定，不能只用页面临时变量模拟持久化。

## 后台与素材需要提供的内容

角色基底、免费初始资产、初始模板与部件关联由固定测试配置提供。本周不开发后台编辑页面。

素材需要能根据相同的部件标识在首页、衣橱和纪念图中复用。统一位置、尺寸、层级和适配范围；表情与动作已确认先做静态可切换表情和姿势，不接角色动画。

## 验收例子

账号 A 选择初始模板甲后，甲成为当前搭配，其他免费初始装扮也可在衣橱使用。换装保存后刷新，仍显示保存后的形象。进入纪念图预览时，相同搭配得到一致的伙伴形象。切换账号 B 不继承 A 的资产增量、余额或回忆。

当前测试采用三套初始搭配、七槽位，演示账号名称固定，不提供昵称编辑；这些是实施默认值，不是正式运营配置。正式母版和素材清单仍后置，不能把测试数量视为尚未完成初始化。

# 内测实施任务详表

版本：v1.1，2026-11-08。配合[总计划](开发实施任务与里程碑.md)与[验收用例](内测验收用例与发布清单.md)使用。45 项中 R00 的 5 项已验收，R01—R06 的 40 项待开始；R00 实际责任与证据见阶段记录，其余角色不表示已安排人员。任务中的方案约束属于实施要求，具体渠道、引擎和费用须经过总计划 D01—D09 的对应决定。

任务状态更新时补负责人、开始／验收日期、提交及证据链接；尚未产生的交付物不是已经存在的文件。验收编号范围如 AU01—AU08 表示包含区间内全部适用项，条件不适用须说明依据。

## R00 范围、资源与验收口径

### R00-01 固定本次内测范围

- **状态／负责**：已验收；Codex 执行与自验、用户确认范围；开始／验收日期 2026-11-08，基线 `8c5ba35`，分支 `codex/internal-alpha-r00-20261108`；[实际交付与证据](R00阶段验收记录.md#逐任务交付与验收)。
- **前置输入**：无；读取总计划、产品规则及整理交接。
- **目标与效果**：把演示成果与内测必须具备的真实能力分开。

1. 按登录、游玩、抽取、衣橱、回忆、订单、运营逐项列“保留／接真实服务／测试模拟／后置”；列出六套服装与两模板的投放目标。
2. 将 D04 付费边界、D05 内测对象与设备提交确认；未答项标责任人与最迟关口。

- **交付物**：内测范围表、非目标清单、D04/D05 决定，写回产品规则与本计划。
- **验收**：PR01；每个游客入口都有范围归属，不把云端／动画当作已实现。
- **异常／回退**：范围有争议则只暂停受影响项，记录差异；不得新增路线任务、旅程结束或静默取消购买入口。

### R00-02 建立决策、依赖与责任台账

- **状态／负责**：已验收；Codex 执行与自验、用户确认范围；开始／验收日期 2026-11-08，基线 `8c5ba35`，分支 `codex/internal-alpha-r00-20261108`；[实际交付与证据](R00阶段验收记录.md#逐任务交付与验收)。

- **目标与效果**：后续能知道为什么没开工、由谁补什么。

1. 为 D01—D09 填待答问题、可选方向、需要证据、决策责任与截止关口。
2. 把任务绑定实际负责人；一人可兼任，但美术源文件、真机验证、云服务权限不能留空。
3. 标明哪些工作可独立继续；外部等待与工程工作分开记录。

- **交付物**：决策台账、角色分工、受阻事项表；未确定人选明确标出。
- **验收**：PR01、PR02；任一任务缺资源时可定位依赖，不能“默认已有”。
- **异常／回退**：不虚构人员／预算和日期。缺少资源只影响对应关口，不借此停止全部可开展设计。

## R01 账号、数据与服务方案

### R01-01 确定实际登录与恢复路径

- **状态／负责**：待开始；实施＋产品确认。
- **前置输入**：G0；D01/D02 所需资源信息。
- **目标与效果**：让游客拥有可恢复的真实身份，替换本机 A/B 选择。

1. 比较实际可接的一种主登录渠道，查询官方接入条件、可用环境、费用和恢复方式；不凭历史高保真稿锁定渠道。
2. 画首次／回访／会话失效／退出／凭证丢失／绑定冲突状态图；若渠道不用验证码或绑定页，明确其不适用并移除无效入口。
3. 确定可信用户 ID 与外部身份映射，未来接黄晓西不以手机号或显示名直接合并进度。

- **交付物**：D01 决策、账号生命周期及相关页面清单，更新数据契约和交互标准。
- **验收**：AU01—AU08、PR02；所有状态都有可执行下一步，恢复不能绕过身份验证。
- **异常／回退**：渠道不可用就评审替代方案；不能以任意昵称／本机编号冒充真实账号。

### R01-02 细化前置守卫与账号页面

- **状态／负责**：待开始；实施＋产品确认。
- **前置输入**：R01-01；既有三主场景与返回规则。
- **目标与效果**：扫码新用户、回访用户和中途失效都能回到正确位置。

1. 为登录、初始化、账号资料、恢复／绑定列进入条件、输入、按钮、成功／错误／取消／刷新状态；按实际渠道设计，避免空页面。
2. 设计完整 returnTo 与点位参数保存、来源校验、初始化后返回；登录和初始化无游玩菜单。
3. 确定退出前草稿处理、写入中退出、其他标签账号切换、登录到不同账号时的待处理请求隔离。

- **交付物**：完整账号交互表和整套相关页面状态稿；冻结页面职责后再做样式实现。
- **验收**：AU02—AU08、SY03、UX01；不得登录即记录到访，不把旧账号的待付／抽取请求重放给新账号。
- **异常／回退**：异常时回可恢复入口，保留原账号安全隔离的草稿；不借自动重试跨账号写入。

### R01-03 设计数据归属与版本

- **状态／负责**：待开始；实施。
- **前置输入**：R01-01；产品规则、现有本地结构。
- **目标与效果**：云端模型支持账号全局装扮和景区分账，兼容未来扩展。

1. 列账号／外部身份／伙伴／拥有／保存搭配、景区余额／资格／解锁／经历／流水、订单、作品的归属与稳定 ID。
2. 明确结构版本、配置版本、搭配版本、素材版本、模板版本各自含义；定义分页顺序和同一时点的稳定排序。
3. 确定 D07：是否导入演示、草稿范围、退出及数据删除申请流程；导入不能信任客户端余额或伪造到访。

- **交付物**：更新数据契约：实体关系、唯一约束、版本冲突、迁移与保留范围。
- **验收**：SY01—SY05、BZ04、BZ07、MW06；任一记录能追到账号、景区和来源。
- **异常／回退**：未知历史字段标 legacy；不编造来源，不以清空存档完成迁移。未定导入政策不执行导入。

### R01-04 确定事务、幂等与接口失败语义

- **状态／负责**：待开始；实施。
- **前置输入**：R01-03。
- **目标与效果**：首次领奖、抽取、订单和重试在并发下仍符合规则。

1. 逐一列命令的可信身份、输入、写集合、唯一约束、结果和错误；requestId 绑定账号＋用例＋输入指纹。
2. 设计领奖事务及账号全局拥有约束；两个不同池甚至不同景区并发抽取同一资产时，也要重算合法候选而非重复扣次发物。
3. 设计超时查询、输入冲突、资源版本冲突、重试窗口与返回语义；框架／数据库选定后验证实现，不用按钮禁用代替。

- **交付物**：更新数据契约及接口样例、事务边界图、并发测试夹具设计。
- **验收**：BZ02—BZ12、SY02、SY04；同请求重放返回原结果，新操作使用新请求，不能重复结算。
- **异常／回退**：事务或约束无法保证则调整存储方案后再开工；明确失败无写入和未知结果两种状态。

### R01-05 确定环境、会话与文件保存方案

- **状态／负责**：待开始；实施＋发布负责人。
- **前置输入**：R01-01/03/04；D02/D09。
- **目标与效果**：身份、数据库、文件与日志能在实际环境连起来。

1. 给出开发／测试／内测环境、服务运行、HTTPS、认证会话及退出撤销方案；客户端只拿所需权限，秘密留服务侧。
2. 定义作品准备快照→渲染／上传临时文件→校验→完整提交→读回的流程；校验文件归属、格式、尺寸、哈希和存储存在性，处理中结果可查询。
3. 区别可信经历／搭配与上传像素可信；选择浏览器或服务端渲染，验证资源跨域和确定帧导出；规划私有作品读取、URL 更新、孤儿文件清理、备份恢复。

- **交付物**：D02 决策、D09 候选方案、部署／存储图、会话与访问规则、成本估算口径。
- **验收**：AU05/AU08、MW02—MW07、OP01—OP05；同账号可跨设备读，其他账号不能读／写，文件和记录失败可恢复。
- **异常／回退**：不得先默认公开图片桶；需外部采购或部署资源则确认具体方案。D09 可待 G2 验证后最终冻结。

### R01-06 接口评审与最小接入设计

- **状态／负责**：待开始；实施＋验收。
- **前置输入**：R01-01—05。
- **目标与效果**：开工前接口、页面与数据结果能够逐项对齐。

- **验收**：PR02、AU01—AU08、BZ01—BZ12 的设计覆盖；D01/D02/D07 明确，D09 有可测试方案。

## R02 动画换装技术样板

### R02-01 冻结样板母版与内容

- **状态／负责**：待开始；美术／动画＋实施＋产品确认。
- **前置输入**：G0；R00-03，D03/D06 初步方向。
- **目标与效果**：两套服装和全部动作都属于同一位黄晓西。

1. 选母版正面、脸部、头身比例、基准站姿及两套差异服装；保持既有业务 assetId。
2. 确定发型前后层、颈口、袖口、裙裤、鞋、银饰的分层／遮挡与可编辑源文件。
3. 列静态 pose／expression 资产与 idle、blink、tapResponse 运行状态的关系；基础连续回应不可被未获得的奖励动作卡住。

- **交付物**：D06 样板确认、母版／源文件清单、部件 ID 对照、动作与奖励映射草案。
- **验收**：PR03、AN01；用户能辨认是同一角色，图层和可编辑源真实存在。
- **异常／回退**：颈口或白边问题先修母版；只改一个变量，失败版本不传为新母版。

### R02-02 比较并验证候选渲染路线

- **状态／负责**：待开始；实施＋美术／动画。
- **前置输入**：R02-01；D02 目标环境、D05 设备候选。
- **目标与效果**：用可运行证据选技术，避免先开发完衣橱再返工。

1. 按实际源文件筛选适用的分层骨骼／变形或三维路线；记录不适用原因，不强行全部试做。
2. 用同一角色、两套服装、相同动作与导出目标做小样，核实官方 Web 支持、制作工具、授权、资源体积与维护成本。
3. 测部件更换、同一动画绑定、确定帧出图及故障降级，形成推荐与备选；未经确认不购买授权。

- **交付物**：D03 技术比较记录和至少一个满足核心能力的可运行候选；其他候选给排除证据。
- **验收**：AN01—AN05；静态 GIF／整套视频播放不能当可混搭的连续动画证明。
- **异常／回退**：所有路线失败则回母版或能力要求评审，不进入批量服装生产。

### R02-03 落实动画状态与互动

- **状态／负责**：待开始；实施＋美术／动画。
- **前置输入**：R02-02 的有效候选。
- **目标与效果**：待机、眨眼、点击回应自然连续且可控。

1. 定义 loading→ready／idle→回应→idle、error、hidden／disposed 状态；眨眼与表情／姿势的层级明确。
2. 建议点击回应播放中合并多余点击、播完回待机，不无限排队；切衣服按原子资源切换避免半身裸露或旧回调覆盖。
3. 前后台暂停／恢复、切页释放、重复挂载、低性能与加载错误有处理；持续动画不可依赖后台计时器精确运行。

- **交付物**：动画状态机、输入事件／生命周期接口、运行录像和错误处理说明，写回渲染规范。
- **验收**：AN02、AN03、AN05、AN06；持续点击、20 次切页和切后台后无错状态或重复循环。
- **异常／回退**：资源失败显示可重试反馈；静态回退是故障态，不作为“必须有动画”的验收通过。

- **前置输入**：R02-01/03。

- **交付物**：完整手账／作品／票夹页及状态矩阵，订单测试数据与环境隔离。
- **验收**：MW01—MW07、BZ11/BZ12、UX03/UX05；模拟成功不触发真实收费或生产到账。
- **异常／回退**：真实支付未获确认则按已确认模拟范围交付；若内测要求真实支付，则 R06-04 必须提前且成为 G5 前置。

### R04-05 提供最小配置发布与问题查询

- **状态／负责**：待开始；实施＋发布／运营。
- **前置输入**：G3；R01-05，实际维护人员明确。
- **目标与效果**：不做大后台也能正确维护和定位问题。

1. 提供有 schema 校验、差异预览、操作者和版本记录的配置发布工具；内部 CLI／受控脚本可满足，不擅加完整后台 UI。
2. 可按脱敏账号 ID、requestId、visit/draw/order/work 查询关联，不能给普通游客开补发、改余额权限。
3. 停用点位／资产／模板保留历史引用，发布前验证池候选与素材齐全；回退配置不撤销用户已获资产。

- **交付物**：配置发布／回退操作说明、只读诊断工具和权限记录。
- **验收**：OP02/OP05/OP06、BZ04、MW06；故障可定位到具体业务操作，坏配置不能上线。
- **异常／回退**：误配置先停受影响入口并回退发布；补偿操作另有审计和确认，不直接手改余额表。

### R04-06 全页面状态与游玩体验复核

- **状态／负责**：待开始；验收＋实施＋产品确认。
- **前置输入**：R04-01—05。
- **目标与效果**：所有页面连贯、温暖、有反馈，未回退成工具网站。

1. 按游客操作表覆盖首次／回访、加载、空态、无效 ID、锁定、收齐、资格已领、处理中、失败及返回。
2. 功能和恢复一轮，跳转／冗余／引导一轮；视觉按整套稿逐页另验，滚到底检查背景和导航。
3. 检查键盘、触控、焦点、实际字体、角色裁切、获得示例和收集进度；对用户可见差异列清原因。

- **交付物**：全页状态清单、两轮缺陷／修复及视觉对照、G4 结论。
- **验收**：UX01—UX05；全部范围可独立游玩，无空按钮、错误奖励引导或未解释设计差异。
- **异常／回退**：缺陷回到所在模块局部修复；纯视觉修正不能顺带改经济规则或旧作品。

## R05 内测验收、发布与观察

2. 检查依赖、环境变量示例、启动／迁移、服务 API 和发布资源清单；不公开研究或个人存档。
3. 锁定设备、网络、负载、恢复与容量口径；此后变化按影响重新测试。

3. 注入数据库回滚、超时和响应丢失，核对请求结果、资格、流水、拥有、作品一致。

- **验收**：AU01—AU08、BZ01—BZ12、SY01—SY05、MW02/MW03/MW07；阻断缺陷为零。
- **异常／回退**：任何越权、重复发奖、负余额或丢图均阻止发布，不能以 UI 防误点掩盖服务失败。

### R05-03 执行真机、视觉与完整主线验收

2. 测连续动画、换装、切后台、键盘、弱网、资源失败、长手账；对照每页状态稿与底部布局。
3. 实际保存并在相册／文件中打开 PNG，测试可用的系统分享与取消／不支持降级，旧作品不变。

- **交付物**：真机环境表、录屏、逐页截图、测量原始数据、PNG 与 UX 差异清单。
- **验收**：AN01—AN08、MW04—MW07、UX01—UX05、OP04；目标设备无阻断问题。

### R05-04 演练备份、恢复与回退

- **状态／负责**：待开始；实施＋发布／验收。

- **交付物**：内测 URL、版本与发布时间、冒烟结果、支持／监控和回退入口。
- **验收**：OP01—OP08、AU01、MW05；用户可以实际到达，生产写接口不接受演示成功标记。
- **异常／回退**：错误触发停止扩大发放；必要时进入维护／只读并按手册回退，保护已提交用户数据。

### R05-06 组织试用与问题闭环

- **状态／负责**：待开始；产品确认＋验收＋实施。

- **异常／回退**：有阻断问题则暂停扩邀；新增产品要求另评估，不直接塞入当前修复。

- **验收**：OP08、PR01—PR03；另一实施者按文档可接手，提交、配置及证据一致。
- **异常／回退**：缺现场资源可停在已交付内测状态；未解决主线问题继续修复，不自动进入现场。

## R06 真实景区试点准备与执行

### R06-01 落实真实场景和现场范围

- **状态／负责**：待开始；产品确认＋运营＋实施。
- **前置输入**：G5；景区／商家／运营联系人到位。
- **目标与效果**：测试地名和画面换成可核实的实际游玩内容。

1. 确定试点区域、点位／活动、开放与核验条件、奖励及池关联；核实经营方操作责任。
2. 提供真实图片／地图依据及授权，明确示意地图与导航边界；不伪造 GPS 轨迹。
3. 生成现场物料清单、二维码投放／替换／失效方案、目标手机与网络检查路径。

- **交付物**：试点配置版本、事实素材清单、点位／商家确认、现场验收计划。
- **验收**：PI01、BZ03/BZ04；每个物料匹配正确场景与点位，内容可追溯。
- **异常／回退**：资料缺失不猜位置或权益；保留内测配置独立，不能直接把测试码当生产码。

### R06-02 实现并验证现场到访凭证

- **状态／负责**：待开始；实施＋现场验收。
- **前置输入**：R06-01；身份与事务基础。
- **目标与效果**：有效到访依据可说明，失败与作弊边界明确。

1. 依据现场条件选择码签名／轮换、位置或其他证据组合；明确复制码、定位拒绝、弱网和无权限时的替代核验。
2. 后端验证凭证、点位／景区／有效期及请求防重；记录测试或真实来源，不信任客户端位置或成功标志本身。
3. 现场逐点验证首次、重复、异地点码、过期、权限拒绝、网络中断；正式政策另确认，不沿用演示 60 秒当规则。

- **交付物**：真实核验方案、配置／物料、现场正反例与残余限制。
- **验收**：PI02、BZ03—BZ06、SY02；成功才记录，失败无奖励；复制／转发风险有测试结论。
- **异常／回退**：若无法可靠核验，明确降级与人工处理并确认试点范围；不能宣称扫码已证明到场。

### R06-03 交付店员最小核验与运营支持

- **状态／负责**：待开始；实施＋运营＋现场验收。
- **前置输入**：R06-01/02；店员身份资源。
- **目标与效果**：游客完成消费／体验后，由有权限的店员核验，资格独立。

1. 明确店员与商家／活动权限、登录／退出、游客核验凭证、确认对象、已核验与失败反馈。
2. 提供最小操作端和核验审计；错商家、跨活动、重复核验、游客冒充店员均被拒绝。
3. 培训商家和运营，演练游客不在旁、误核验争议和服务中断的处理；补偿权限独立可追溯。

- **交付物**：店员操作端、权限与审计、培训说明、支持和争议处理路径。
- **验收**：PI03、AU08、BZ05/BZ06；店员不能访问无关游客隐私或修改余额，游客端无真实“自选成功”。
- **异常／回退**：核验结果不确定先查原请求；误操作按审计处理，不手删历史流水掩盖。

### R06-04 按决定接真实支付

- **状态／负责**：待开始；实施＋支付资源负责人＋验收。
- **前置输入**：D04 要求真实收款时；渠道／主体／费用已确认；若内测需收款则前置至 G5。
- **目标与效果**：真实订单、到账和差错处理与演示彻底分开。

1. 查询所选渠道官方接入与回调要求，设计下单、处理中、成功、关闭／失败、迟到通知、查单及对账；不要机械复用 demo 终态。
2. 服务端核验签名、金额／币种／商户／订单及唯一到账，客户端成功提示不能发次；购买仍不解锁池。
3. 落实退款／争议、次数已使用时处理和渠道故障政策，先确认再实现；现场走小额真实验证及通知重放。

- **交付物**：支付专项设计、业务政策确认、接口与对账报告、真实验证凭据。
- **验收**：PI04；假通知不到账、重复只一次、晚到状态可解释；真实扣款与次数一致。
- **异常／回退**：未启用真实收费时标为条件任务而非失败或已完成；渠道未具备则保持已确认模拟／免费范围，不开收费入口。

### R06-05 现场全程验收与试点交接

- **状态／负责**：待开始；产品确认＋现场验收＋实施。
- **前置输入**：R06-01—03；R06-04 适用时必须通过。
- **目标与效果**：游客、商家和运营分别完成真实职责，能够开始有限试点。

1. 新游客现场登录、领装、到访、抽取、动画换装、回酒店／跨日制作及另一设备回看；实际保存 PNG。
2. 店员核验与运营查询各自完成，覆盖弱网／错码／已领奖／服务故障，核对服务记录及物料。
3. 记录现场限制、试点范围、支持责任、监控／回退条件，完成 G6 与交接；后续扩区重新核验配置。

- **交付物**：现场验收报告、试点发布版本、角色培训与支持／回退说明。
- **验收**：PI01—PI05、UX05、OP08；全程不依赖开发者改数据，模拟能力明确隔离。
- **异常／回退**：任何现场主线／核验／收费错误阻止正式试点，先回对应任务；保留已完成内测成果。

## 技术衔接必须写清的六件事

1. **身份**：会话→可信 accountId→业务授权；请求参数和浏览器存档不决定账号归属。
2. **结算**：到访／活动→事件＋资格＋余额＋流水＋解锁；抽取→结果＋扣次＋全局拥有；每个集合完整提交。
3. **同步**：账号全局拥有与 look，景区余额与经历分开；编辑版本冲突与新库存到达区别处理。
4. **渲染**：静态 pose／expression 奖励与基础连续状态分开；用同一 look 和素材版本承接三个页面，导出明确帧。
5. **作品**：可信来源快照、文件完整性和像素真实性各自定义；业务数据库与对象文件使用可恢复流程，不能宣称天然跨存储原子事务。
6. **回退**：代码、配置、素材、schema、用户写入及图片版本分别核对；冻结旧演示不是正式云数据的备份机制。

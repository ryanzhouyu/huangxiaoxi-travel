## 伙伴与资产输入

当前搭配槽位为 `hair/top/bottom/shoes/expression/pose/background`，是原型实施默认值。固定脸部基底不作为抽取奖励；妆容、连衣裙或新槽位并未在当前配置实现，增加前需确定互斥关系及适配范围。

建议素材描述包含以下字段，属于待实现契约：

| 字段 | 用途与约束 |
| --- | --- |
| `assetId`、`slot` | 与业务库存一致；不可用文件名替代稳定 ID |
| `manifestVersion`、`assetVersion` | 标识本次素材清单及单资产版本；替换文件不覆盖旧版本语义 |
| `previewSource`、`renderSource` | 缩略预览与实际合成来源，可分别提供 |
| `canvas`、`anchor`、`transform` | 基准画布、锚点和偏移；同一坐标规则用于所有渲染位置 |
| `layers`、`zIndex` | 分层及遮挡顺序；同发型可有前后层，不强迫一件只有一层 |
| `compatiblePoses`、`conflicts` | 兼容姿势、互斥槽位／资产，不能承诺任意组合 |
| `fallback` | 缺失时可用的已定义处理，不能静默给用户未拥有资产 |
| `source`、`license`、`identityVersion` | 素材原件、授权及人物母版追溯；未确认标为待核实 |

输出尺寸由页面和模板传入，不能要求同一图片原样缩放就适配全部场景。精确画布和锚点数值在母版样板确认后填写，不凭画板截图推断。

## 渲染端口

目标分为三项能力，当前函数由适配器衔接，不要求立即改名：

| 能力 | 输入 | 输出／失败 |
| --- | --- | --- |
| `validateLook` | 资产引用、姿势、拥有状态、素材清单 | 合法结果或具体不兼容项；业务槽位校验与素材校验都需通过 |
| `renderCompanion` | 保存搭配或明确标记的试穿搭配、清单版本、目标区域 | 同一身份与组合的渲染结果；展示代码示意或真实素材由适配器决定 |
| `composeMemory` | 已保存搭配、经历快照、背景、标题、模板及素材版本 | PNG、尺寸、制作输入指纹；失败不保存作品，保留重试条件 |

衣橱允许本地试穿预览，首页只读保存搭配；制作页从保存搭配取得输入。不能三个页面分别维护一份穿戴逻辑。未拥有资产可以在卡池、图鉴中展示，不因此允许保存。

## 姿势与服装适配

服装与姿势适配采用显式兼容表或姿势变体引用。切换姿势会产生不兼容时先说明限制，保留原搭配；是否提供一键替换属于后续交互方案，不自动换成未拥有服饰。

2026-11-08 内测目标要求连续动画。正式渲染选型前，按[实施计划 R02](开发实施任务与里程碑.md)完成一个母版、两套差异服装和三类基础动作的样板。检查部件混搭、动作衔接、手机性能和静态图片导出后，确定源文件格式、制作方式与兼容范围。

动画状态应明确进入、循环、中断、结束回到待机的规则。点击回应需有连续点击处理，切换页面和进入后台需管理播放与资源释放。角色源文件、绑定或变形数据以及导出姿势必须可以追溯版本。图片合成使用明确静态姿势或确定帧。

人物身份、脸部与整体比例在同一母版下检查，素材探索不能以失败变体作为下一轮默认母版。

## 纪念图与历史作品

- 模板 ID 为 `postcard` 和 `trail`。早期业务原型分别输出 900×1200、900×1400 PNG；当前客户演示使用 `design/demo/postcard.mjs` 与 `visual/print.mjs` 的构图，最终美术交付规格在样板中确认。
- 背景和文字必须匹配选中经历；连线仅表达实际到访顺序，不能冒充 GPS 轨迹。较长经历可在图中摘要展示，作品详情保留完整来源。
- 生成前固定账号、搭配、经历、标题、模板和素材版本；任一改变使旧预览失效。保存后固定图片和快照，不在浏览旧作品时重新合成。
- 真实图片接入需验证加载失败、跨域与画布导出权限；资源必须允许实际 PNG 导出。不存在的素材不得悄悄换成错误地点或错误身份。
- 当前演示作品保留演示标识。输出文字、裁切及背景对比度按实际尺寸检查，不能仅检查图片文件存在。

## 素材阶段的进入与验收

先确认伙伴母版、有限槽位与姿势组合，再以同一母版、两套轮廓差异明显的服装完成可换装动画样板，检查首页、衣橱、纪念图一致性；通过后扩展首批数量。对应[任务详表 R02](内测实施任务详表.md)与[AN 动画验收](内测验收用例与发布清单.md)。原画板中的整张界面图保留为来源，不能当作已具备分层资产。

基础运行状态 `idle/blink/tapResponse` 与奖励资产的 `pose/expression` 分开：游客的基础连续回应不能依赖抽到奖励动作才可用。奖励动作或表情如何参与循环、中断与导出由样板验证并写入兼容表，不自动扩大原有奖池。失败时的静态占位仅为恢复反馈，不能替代内测连续动画验收。

验收包括：只换一件保留其他件；姿势切换符合兼容规则；人物身份一致；缩略图与合成一致；旧作品不变；缺图有恢复；导出 PNG 可打开。正式清单在此接口上扩展，无需提前决定生产工具或供应商。

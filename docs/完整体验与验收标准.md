# 黄晓西完整交互体验与验收标准

文档版本：交互规格 v0.4，核对应用 v0.3.1。更新日期：2026-10-19。当前页面交互以本文为准，16 类页面路由及模块归属见[页面与模块目录](页面模块与初始化范围.md)。游玩布局依据见 [游玩界面设计调整](游玩界面设计调整.md)，历史修复与优化见 [两轮自测报告](两轮自测与优化报告.md)。

本文保留 v0.3.1 共享交互基线：游客连续完成初始伙伴、线上领装、测试打卡、抽取、换装、回忆制作、PNG 保存，并在刷新后恢复进度。验收重点是页面时机、业务后果和异常恢复。当前 demo 已有[黔山同行视觉及演示服装](高保真设计说明.md)，不再以“素材后置”免除界面验收；正式动画与生产素材按[渲染接口](素材与渲染接口规范.md)先做样板。本文不表示本次重新执行全部应用测试。

体验入口为 [旅行衣橱](../design/index.html)。本机访问地址为 `http://127.0.0.1:8765/design/index.html`。旧版页面结构草案保存在 [v0.1 历史目录](../design/archive/v0.1/index.html)，不再作为当前体验入口。

## 实现边界

本轮采用原生 JavaScript 模块及浏览器存储，属于可操作、有连续进度的本地交互原型。两个演示账号的数据在当前浏览器分别保存；账号与库存均非服务端权威数据。部署静态目录后可体验，但跨设备同步、真实账号、真实支付、店员端、现场防作弊和生产环境并发处理尚未接入。

测试码核验确实解析链接或码值并执行记录、发奖与解锁；它验证的是码内容，不能证明游客到场。定位和活动核验在操作入口及记录中明确标为模拟。PNG 由浏览器实际合成和下载，当前使用代码绘制的部件与背景示意，不代表最终黄晓西角色设计或素材生产方案。

## 页面出现与导航规则

| 所处阶段 | 出现的页面元素 | 不应出现的内容 |
| --- | --- | --- |
| 账号入口 | 品牌介绍、两张演示账号卡、存储范围说明 | 顶部产品菜单、底部游玩导航、返回到未建立的伙伴、景区余额 |
| 初始伙伴 | 三套可选择搭配、预览、全部免费说明、确认、换账号 | 游玩导航、卡池、背包入口、足迹或抽取次数摘要 |
| 伙伴／游玩／回忆三个主要场景 | 伙伴与场景、底部三个场景入口；衣橱从伙伴旁的背包进入 | 页面审核目录、任意状态切换器、首页功能说明卡与统计卡 |
| 景区／地点／活动／卡池／套装详情 | 返回、当前内容、当前条件满足的动作 | 底部主导航、无效的抽取入口、无来源的领奖按钮 |
| 从伙伴／领装／抽奖／出图进入衣橱 | 人物与部件同屏、返回、已获部件、试穿、保存并返回、取消 | 底部主导航；跳到其他模块而静默丢失草稿 |
| 制作纪念图 | 日期与经历选择、模板、标题、预览、调整搭配、生成／保存 | 未到访即生成真实回忆；强制结束旅程 |
| 作品详情 | 固定图片、来源经历、PNG 保存、分享、再制作 | 把旧作品随新换装自动改变；将点击分享算成已发布 |

页面审核说明只放在桌面外侧及文档中，手机内不出现“查看页面”“查看状态”工具。当前提供 16 类页面职责，其中账号、打卡核验与次数明细是相较原结构补齐的页面。

## 逐步操作与状态处理

| 环节 | 页面与操作 | 成功结果与下一步 | 取消或异常 |
| --- | --- | --- | --- |
| 进入 | 选择游客 A 或 B | 新账号进入初始伙伴，回访账号恢复已保存进度 | 未登录打开详情链接先进入账号入口，保留原目标 |
| 初始化 | 切换三套预览，确认一套 | 全部初始装扮入库，选中搭配成为默认；首次扫码继续回原点位 | 不允许通过链接跳过初始化；可换账号 |
| 线上认识景区 | 游玩列表进入黔山漫游，查看简介和免费套装 | 景区详情同时呈现地点与卡池，不要求领取路线任务 | 地点及卡池无效编号显示缺失提示，不能冒充其他地点 |
| 免费领装 | 点击领取，结果层选择立即试穿或先收好 | 4 件免费装扮入库；尚未自动穿戴，也未产生到访 | 领取后入口改为已领取／去试穿，不重复入库 |
| 试穿与保存 | 在衣橱按发型、上装、下装、鞋履、表情、姿势、背景分类选择 | 同部位替换，保存后用于伙伴首页及新作品，返回来源页 | 取消有保存／放弃／继续编辑三个选择；未保存不能改变正式搭配 |
| 了解点位 | 查看地点、类型、首次奖励、关联卡池 | 景点提供打卡；商家额外提供独立的店内活动入口 | 已领首次奖励时明确下次只记到访、不再发奖 |
| 测试扫码 | 系统相机扫描测试链接，或在核验页粘贴链接／输入测试码 | 确认后核验并记录地点、时间、方式、当时搭配，同时发次数、解锁卡池 | 无效码与不匹配的地点拒绝；页面输入保留，可更正重试 |
| 重复到访 | 同地点后续到访再次核验 | 记录新经历，不重复发首次奖励 | 同地点同方式 60 秒内抑制连续误点；这是演示防重方案，不是奖励周期 |
| 定位演示 | 点击定位模拟，再选成功或超出范围 | 成功产生带模拟标记的到访 | 失败不记录、不发奖、不解锁 |
| 商家体验 | 先阅读参加条件，再演示店员核验 | 完成活动单独记经历、发奖励、解锁关联池；不必再领一次到店奖励 | 失败无业务变化；同项活动奖励每账号一次，成功后移除领取操作 |
| 选择卡池 | 查看所属景区、余额、收集进度、奖励、概率、套装来源 | 未解锁显示关联地点；已解锁且有余件时显示抽取 | 未解锁不提供抽取操作；全收齐移除抽取和该池购买入口 |
| 抽取 | 单次消耗 1 次景区通用次数 | 从全局未拥有奖励等概率抽取；立即入库，结果可去试穿或返回 | 余额不足提供去打卡／模拟购买；存储失败不扣次不发物 |
| 部件来源 | 点击卡池或套装中的部件 | 已拥有可去试穿；未拥有显示来源池和到访条件，可继续追溯 | 不允许将未拥有部件保存为搭配 |
| 模拟购买 | 选测试套餐，确认模拟成功／失败／取消 | 成功订单发放景区次数；订单与收支可查 | 失败／取消不发次，关闭待支付订单后可到次数明细继续，重复确认不重复到账 |
| 回顾足迹 | 回忆分足迹、作品两页签；按全部、今天或日期范围查看 | 查看经历时间、来源、奖励，选择单条或多条制作 | 线上领装、抽取、购买均不生成虚构足迹；无到访时展示空状态 |
| 制作图片 | 选择经历、日期范围、单页／长图、16 字内标题 | 生成实际 PNG 预览，再保存成作品 | 0 条经历禁用生成；变更经历、模板、标题或搭配后要求重新生成 |
| 制作途中换装 | 从制作页进入衣橱，试穿并保存返回 | 日期范围、模板、标题、勾选经历保持；使用更新后的保存搭配 | 放弃试穿仍回到原制作状态，保持原正式搭配 |
| 保存与分享 | 作品详情下载 PNG；支持时调用系统图片分享 | 作品保留固定图片及经历、搭配快照，可再次制作新的作品 | 不支持直接图片分享的浏览器提示下载后分享；不宣称已发到社交平台 |
| 账号与进度 | 伙伴页进入账号，查看次数收支和模拟订单，切换账号 | 返回同一账号时恢复库存、余额、足迹、搭配与作品 | 存储不可用时显示错误且不覆盖旧数据；重置藏在验收工具中并二次确认 |

## 跨页上下文与状态约束

| 场景 | 必须保留／隔离 | 完成、失败或刷新处理 |
| --- | --- | --- |
| 未进入时直接打开点位码 | 完整核验目标及参数 | 选择账号／必要初始化后回原点；不强制领景区套装 |
| 同类详情切换不同 ID | 完整路由历史 | 返回到真实来源池或地点，不按页面名合并历史 |
| 制作→衣橱→图鉴→套装→返回 | 制作标题、经历、模板及衣橱来源 | 保存／放弃回原制作页；来源入路由参数，刷新后仍可恢复 |
| 衣橱未保存离开 | 独立试穿草稿 | 保存并继续／放弃并继续／继续编辑；正式搭配不受未保存草稿影响 |
| 抽取开启与图片合成期间跳转 | 操作所属账号、提交结果、目标路由 | 暂存导航，操作结束后执行；不能晚弹结果打断新页面，失败恢复按钮 |
| 制作后修改标题／经历／模板／保存搭配 | 预览与输入的对应关系 | 旧预览失效，重新生成；不能以旧图片配新元数据保存 |
| 保存完成作品后开始新制作 | 旧作品图片固定；未完成草稿独立 | 已完成制作选项清理，新制作默认已有全部经历；再制作旧图可带回原选项 |
| 同账号另一标签更新进度 | 当前未保存试穿与正式搭配区分 | 保留脏草稿；正式搭配改变使旧预览失效，不静默丢弃试穿 |
| 另一标签切账号或重置 | 账号隔离、草稿资产合法性 | 同步守卫与地址，失效草稿清理并提示；写入前再次核对账号 |
| sessionStorage 不可用 | 业务进度与编辑存储分别处理 | 仍可进入；草稿仅内存，不承诺刷新恢复 |
| localStorage 满或结构损坏 | 原业务记录 | 写失败不提交半笔业务；读失败显示错误，不自动覆盖坏数据 |

以上描述当前交互行为，完整多标签并发事务尚未实现。目标请求版本与冲突处理见[数据契约](数据模型与业务接口契约.md)。

## 独立验收标准

每个页面同时检查五件事：进入条件是否满足、信息是否属于当前阶段、按钮是否真实有效、操作结果是否保存、返回和异常是否保留上下文。具备页面入口但没有结果，或只能依赖审核工具切状态，不算通过。

| 验收维度 | 必须满足的结果 |
| --- | --- |
| 阶段隔离 | 账号和初始化无游玩导航；详情和任务编辑无主导航；未登录及未初始化链接不能绕过前置条件 |
| 主路径 | 从新账号开始，实际保存出一张 PNG；不依赖预置“已到访”状态 |
| 状态一致 | 领取与穿戴、到访与发奖、当前搭配与旧作品互相独立；余额和奖励可追溯 |
| 防重复 | 领装、同点首次奖励、活动、订单确认不重复发放；抽取全局排重；收齐不扣次 |
| 返回与草稿 | 抽后定位到对应部件；保存回来源；离开试穿有选择；制作中换装保留选择 |
| 异常 | 错码、不匹配点位、模拟核验失败、余额不足、支付取消／失败、存储失败均有恢复路径 |
| 账号保存 | 刷新恢复，A/B 隔离；坏数据不自动清空；重置需明确确认 |
| 显示与导出 | 360／390px 手机与 1440px 桌面无横向溢出；检查返回、固定操作区与图片文字；实际 PNG 解码及下载 |

验收记录见 [浏览器检查明细](../design/verification.json)，业务不变量检查见 [domain.test.mjs](../design/tests/domain.test.mjs)，完整操作脚本见 [browser-flow.js](../design/tests/browser-flow.js)。脚本在独立浏览器上下文中测试，不改写当前体验账号。

业务测试当前覆盖 14 组规则，二维码的内容校验边界不变。[游玩布局检查](../design/game-verification.json) 覆盖四个尺寸的关键场景、入口遮挡、同屏操作及交互反馈；新增边界和优化检查见两轮报告。自动检查不能代替对游戏感与视觉方向的审阅。真实移动设备的系统分享与相机链路尚未实机验证。

持续回归与发布清单以[测试与发布验收](测试与发布验收.md)为准；本节历史结果不能代替未来改动后重新执行。服务和素材接入条件见[实施计划](开发实施任务与里程碑.md)，不能把本地交互规则直接当作已完成生产服务。

# 黄晓西数据模型与业务接口契约

更新日期：2026-10-19。状态：当前结构核对与后续契约设计。现状取自 `design/data.mjs`、`design/store.mjs` 和 `design/app.mjs`；下文的目标字段、统一命令与错误码尚未全部落地，不是已上线 API。

本阶段先定义模块调用语义，暂不绑定 HTTP 路径、数据库或云平台。真实服务选型后再补充传输层与数据库约束，不改变[已确认业务规则](一期产品规则与业务流程.md)。

## 配置与用户数据

| 实体 | 主标识及关联 | 约束 |
| --- | --- | --- |
| Scene 景区 | `sceneId`；默认套装、点位、卡池、套餐 | 余额、到访和回忆的景区边界 |
| Point 点位 | `pointId` → `sceneId`；类型、关联池、首次奖励 | 多点可共享池；商家到店与活动分开 |
| Activity 活动 | `activityId` → 点位／景区；条件、核验方式、奖励 | 独立领奖资格，不因到店自动完成 |
| Pool 卡池 | `poolId` → 景区；套装及资产引用、关联点位 | 可抽资产 ID 去重；跨池同资产仍是一项拥有记录 |
| Outfit 套装 | `outfitId` → 多个资产 | 拥有部件与集齐整套分别计算 |
| Asset 资产 | `assetId`；槽位、套装、素材及兼容关系 | 统一 ID，不因不同来源复制成另一项资产 |
| Package 套餐 | `packageId` → 景区；次数、测试价 | 订单创建时保存快照，不随配置修改历史订单 |
| Companion 伙伴 | 账号的持续身份及当前 `look` | 固定脸部身份；初始选择不限制其他初始资产 |
| Ownership 拥有记录 | 账号 + `assetId` | 不重复拥有；获得来源可追溯 |
| Claim 领奖资格 | 账号 + 景区 + 类型 + 来源 ID | 点位、活动、免费套装分别判断，不按页面入口判断 |
| Visit 到访事件 | `visitId` → 账号、景区、点位、可选活动 | 时间、方式、模拟标记、奖励结果和当时搭配快照 |
| Wallet / Ledger 次数及流水 | 账号 + 景区；流水关联操作／订单 | 余额非负整数；每笔增减能找到业务来源 |
| Unlock 解锁 | 账号 + `poolId` → 首次有效来源事件 | 买次数不解锁；共享池到访任一关联点解锁 |
| Draw 抽取记录 | `drawId` → 账号、景区、卡池、资产、请求 | 扣次与入库同成同败，结果先持久化再展示 |
| Order 模拟订单 | `orderId` → 账号、景区、套餐快照 | 金额、次数固定；仅成功到账一次 |
| Work 作品 | `workId` → 账号、景区、经历、搭配及输出快照 | 保存后不可随新搭配、模板或素材更新而重绘 |

目前所有场景配置均为测试数据，不是正式运营数值。配置引用需校验存在性、所属景区、资产去重和兼容关系；配置下架不能删掉用户已获得资产或历史结果。

## 当前存储与目标结构映射

当前 localStorage 键为 `hxx.interactive.v2`，顶层为 `{version: 2, current, accounts}`。`current` 是本浏览器共用的演示账号选择，不是独立的生产登录会话。

| 当前账号字段 | 当前表达 | 后续目标及迁移注意 |
| --- | --- | --- |
| `name`、`initialized` | 名称及是否建立伙伴 | 保留初始化语义，真实账号身份另接适配器 |
| `owned`、`look` | 已拥有 ID 数组与七槽位搭配 | 可增来源与版本，不能丢失已拥有项 |
| `gifts`、`claimed`、`unlocked` | 领取与解锁 ID 数组；如 `point:gate` | 多景区需明确复合归属；不能仅凭同名点位合并资格 |
| `balance` | 单测试景区余额标量 | 多景区目标为按 `sceneId` 分账；旧余额只能归入原 demo 景区 |
| `events`、`ledger`、`draws` | 到访、流水及抽取数组 | 当前单景区部分归属隐含；增显式归属时保持原 ID 和来源 |
| `orders` | `pending/paid/cancelled/failed`；可选 `sourcePool` | `sourcePool` 仅供返回，不改变余额归属；缺失仍支持通用返回 |
| `works` | 图片 data URL、事件 ID 与快照、搭配、标题、模板 | 现无完整素材／模板版本契约；增字段不重生成旧作品 |

当前代码的 `scene`、事件 ID 等命名保留兼容映射，不能直接改字段名破坏旧存档。未来增 `schemaVersion`、`revision`、`sceneId`、`manifestVersion`、`templateVersion` 时，需经过迁移测试；历史版本无法还原的信息标为 legacy，不伪造版本或来源。

UI 草稿保存在按账号分隔的 sessionStorage 中，包括试穿、制作选择和返回来源；图片预览为会话状态。sessionStorage 不可用时允许失去草稿恢复能力，但不能导致入口崩溃或覆盖业务进度。

## 目标字段字典

下表用于后续接口实现，当前存档仍按上一节映射读取。`Id` 为非空稳定字符串，`Time` 为带时区的 ISO 8601 字符串；数量／余额为安全非负整数，`delta` 为非零有符号整数，ID 列表不重复。未标可选者均必填，额外业务字段需要显式定义后再加入。

| 结构 | 必需字段与类型 | 可选或兼容字段 |
| --- | --- | --- |
| `Look` | 七个槽位各为 `assetId: Id` | 新槽位另设兼容规则；未知字段不直接作为可穿资产 |
| `OwnedAsset` | `accountId, assetId, sourceType, sourceId: Id`；`acquiredAt: Time` | 历史来源无法还原时 source 标 legacy，不编造抽取 |
| `RewardClaim` | `accountId, sceneId, sourceId, requestId: Id`；`kind: point/activity/gift`；`at: Time` | 无；唯一键由账号＋景区＋类型＋来源组成 |
| `Visit` | `id, accountId, sceneId, pointId, requestId: Id`；`at: Time`；`method: qr/geo-demo/staff-demo`；`demo: boolean`；`reward: integer`；`unlocked: Id[]`；`look: Look` | `activityId: Id`；当前活动事件以后显式补此关联 |
| `LedgerEntry` | `id, accountId, sceneId, operationId: Id`；`at: Time`；`delta: integer`；`balanceAfter: integer`；`reasonType: visit/activity/draw/order` | `label: string`，展示文案不用于结算或关联 |
| `DrawResult` | `id, requestId, accountId, sceneId, poolId, assetId: Id`；`at: Time`；`balanceAfter: integer` | `candidateVersion: string`，配置可变时补充以追溯候选 |
| `DemoOrder` | `id, requestId, accountId, sceneId, packageId: Id`；`count: positive integer`；`amountMinor: integer`；`currency: CNY`；`status: pending/paid/cancelled/failed`；`at: Time`；`demo: true` | `sourcePool: Id`、`updatedAt: Time`；当前 price 为十进制字符串，转换金额需精确到分 |
| `Work` | `id, requestId, accountId, sceneId: Id`；`title: string`；`at: Time`；`eventIds: Id[]` 非空；`eventSnapshots: Visit[]`；`look: Look`；`templateId, templateVersion, manifestVersion: string`；`image: ImageRef` | 旧作品版本字段允许显式 legacy；保留旧图片原字节 |
| `ImageRef` | `kind: inline/url`；`mime: image/png`；`width, height: positive integer`；`value: string` | inline 为当前 data URL；url 只在文件适配器已实现后使用 |
| `Revision` | 账号聚合的非负整数版本，由存储用例递增 | 当前 version:2 是结构版本，不是此并发 revision |

配置结构除实体表中的关联外，至少包括 `id/name`；点位具有 `sceneId/kind/reward/poolIds`，卡池具有 `sceneId/outfitIds/assetIds/pointIds`，套餐具有 `sceneId/count/amountMinor/currency/demo`。测试码属于核验配置，未来服务侧验证材料不能放进普通目录查询返回。

真实服务以可信会话确定账号，以服务端时间记录业务时点；当前演示时间来自浏览器。客户端可另传显示时区，不以可改的客户端时间判断领奖资格。真实定位／店员凭证的字段需接入时扩展，不能将模拟 enum 当成已经实现的真实核验方式。

## 命令参数与结果最小结构

每个写命令的共同上下文为 `{requestId, sceneId, expectedRevision?}`，初始化及账号全局搭配不强制 sceneId。下表字段是上下文之外的参数；结果通过下一节的统一 envelope 返回，写操作均带最新账号 revision。显示名不作为引用键。

| 命令 | 参数 | `data` 最小内容 |
| --- | --- | --- |
| `initializeCompanion` | `starterId: Id` | `initialized: true, ownedAssetIds: Id[], look: Look` |
| `claimScenicGift` | 无额外字段 | `alreadyClaimed: boolean, grantedAssetIds: Id[]`；重复结果保留原发放列表 |
| `verifyVisit` | `pointId: Id, method, code?: string, proof?: object` | `visit: Visit, balance: integer, newlyUnlockedPoolIds: Id[]` |
| `verifyActivity` | `activityId: Id, proof: object` | 同上；模拟选择在演示适配器验证，非生产信任凭证 |
| `drawReward` | `poolId: Id` | `draw: DrawResult, remainingAssetIds: Id[]` |
| `createDemoOrder` | `packageId: Id, sourcePool?: Id` | `order: DemoOrder` |
| `settleDemoOrder` | `orderId: Id, outcome: paid/cancelled/failed` | `order: DemoOrder, credited: boolean, balance: integer` |
| `saveCompanionLook` | `look: Look, expectedRevision: Revision` | `look: Look` |
| `renderMemoryPreview` | `eventIds: Id[], title: string, look: Look, templateId, manifestVersion` | `previewId: Id, image: ImageRef, inputStamp: string`；返回精确模板版本 |
| `saveMemoryWork` | `previewId: Id, inputStamp: string, expectedRevision: Revision` | `work: Work`；经历、图片及快照从可信预览取得，不只信任客户端任意图片 |

`getProgress(sceneId)` 返回该景区余额、解锁、领取、经历、作品以及账号拥有和搭配；`getCatalog(sceneId, entityType?, id?)` 返回对应配置和只读状态；`getRequestResult(requestId, operation)` 用于请求超时恢复。服务接入时明确这些视图的分页和文件地址有效期，本地小样板无需提前引入复杂查询框架。

目标远端预览需有可恢复的预览存储或可信校验机制；本地适配器先在会话中实现等价输入绑定。不要把浏览器传入的 `inputStamp` 当成防篡改凭证。

## 状态变化

| 对象 | 合法变化 | 必须保持 |
| --- | --- | --- |
| 初始化 | 未建立 → 已建立 | 一次发放全部初始资产，确认选定搭配；重试不重复建立 |
| 卡池 | 未解锁 → 已解锁；剩余候选由库存派生 | 收齐是派生状态，不是独立可写的余额状态；未解锁不能抽 |
| 试穿 | 正式搭配 → 草稿 → 保存／放弃 | 草稿不影响首页与作品；未拥有或不兼容资产不能保存 |
| 订单 | `pending` → `paid` / `cancelled` / `failed` | 当前终态不重新支付；失败后新建订单。关闭弹层不自动取消待付订单 |
| 制作 | 编辑 → 合成中 → 可保存预览 → 已保存作品 | 失败回编辑；输入变化使预览失效；再制作生成新作品 |

不建“旅程开始／结束”状态机。到访事件按景区、时间自然累积；路线是实际到访顺序示意，不代表完整 GPS 轨迹。

## 模块调用契约

以下是待实现的统一应用层接口名。当前导出函数在最后一列映射，不要求一次改名。所有查询／写入都以调用时身份校验账号；未来远端账号由可信会话取得，不能相信客户端随传的账号 ID。

写命令统一携带 `requestId`，需要编辑覆盖保护时再带 `expectedRevision`。目标返回 `{ok: true, data, revision}` 或 `{ok: false, error: {code, message, retryable}, requestId}`；现实现抛错，由兼容层转换。

| 用例 | 输入要点 | 成功输出与写入范围 | 当前实现 |
| --- | --- | --- | --- |
| `getProgress` | 当前身份、景区 | 库存、搭配、余额、解锁及进度视图；只读 | `readDB` 及页面查询 |
| `getCatalog` | 景区／点位／池 ID | 配置与真实拥有／解锁派生状态；无效 ID 拒绝 | `data.mjs` 索引、`eligible` |
| `initializeCompanion` | 初始模板 | 伙伴、全部初始资产及默认搭配，一次提交 | `initialize` |
| `claimScenicGift` | 景区 | 首次发放／已领取结果、资产列表；不产生到访、不换装 | `gift`，目前固定 demo |
| `verifyVisit` | 点位、方式、码内容或验证凭证 | 事件、首次奖励、余额、解锁集合；同一提交重试返回原结果 | `checkin`，码核验与定位模拟 |
| `verifyActivity` | 活动、验证凭证或模拟选择 | 独立活动事件、奖励及解锁；与到店资格分开 | `activity`，目前固定 craft |
| `drawReward` | 卡池 | 已持久化奖品、余额及收藏变化；重试返回同结果 | `draw` |
| `createDemoOrder` | 套餐、可选来源池 | 待付订单、景区／数量／金额快照，不加次数 | `createOrder` |
| `settleDemoOrder` | 订单、模拟结果 | 订单状态、到账结果；`paid` 一次入账 | `pay` |
| `saveCompanionLook` | 完整搭配、预期版本 | 验证拥有／槽位／适配，保存新搭配；不发资产 | `saveLook` |
| `renderMemoryPreview` | 有效经历、已保存搭配、标题、模板、素材版本 | PNG 与输入指纹，不保存作品、不修改业务进度 | `composeImage` 与页面校验 |
| `saveMemoryWork` | 预览、输入指纹及来源快照 | 不可变作品、图片存储结果；重复请求返回原作品 | `saveWork` 与页面校验 |

退出账号、过滤地图、切换分类、试穿和关闭结果层不是发奖／扣次命令。`renderMemoryPreview` 的图片如何传输及未来文件存储路径，待服务部署方案确定；模块语义已明确，不提前假定上传服务已存在。

## 原子性与重复处理

当前 `commit` 先复制数据库，业务变更完成后统一写入 localStorage；保存失败时不提交内存状态。它只能保证本次浏览器操作的一致提交，不能阻止多标签同时从旧快照覆盖对方更新。

后续契约要求：

1. `requestId` 按账号和用例范围去重，保存输入指纹与结果。同 ID 同输入返回原结果；同 ID 不同输入返回 `REQUEST_CONFLICT`，不能重做业务。客户端重试保持原 ID；新一次主动操作才建新 ID。
2. 领奖唯一约束为账号、景区、奖励类型及来源。重试不新增事件；真正再次到访可以新增零奖励事件。当前 60 秒同点同方式抑制只是演示防误点默认值，不定义正式到访周期。
3. 抽取在同一事务内核对池、解锁、候选和余额，确定随机结果、扣次、写拥有及结果；不能先扣次再异步发物。全池无候选优先显示收齐，不引导该池购买。
4. 订单终态与到账流水同事务提交，按订单唯一入账；失败／取消不加次，重复回调返回原状态。
5. 超时后先查 `requestId` 的既有结果；查不到才用同 ID 重试。真实服务中的去重存储、唯一约束、锁或版本冲突需实际实现并测试，不用按钮禁用代替。
6. 作品持久化失败不提示保存成功，保留可重试预览。服务接入后图片与作品元数据需可恢复地完成，避免有记录无文件；采用何种提交／清理机制在适配器设计中明确。

当前 `checkin`、`activity`、`draw` 等仅有部分请求 ID 防重，尚无完整输入指纹冲突判断；`revision` 也尚未实现。它们是后续验收项，不作为本轮已完成能力。

## 错误与页面恢复

| 目标错误码 | 条件 | 页面处理 |
| --- | --- | --- |
| `AUTH_REQUIRED` / `INITIALIZATION_REQUIRED` | 身份或初始化不满足 | 保存完整目标，进入相应前置阶段后恢复 |
| `NOT_FOUND` / `INVALID_INPUT` | ID 无效、缺字段、格式不合法 | 明确指出；保留可更正输入，不默认替换成别的点位 |
| `VERIFICATION_FAILED` | 错码、点位不匹配或核验失败 | 无事件／奖励／解锁变化，可更正重试 |
| `ALREADY_CLAIMED` | 活动等资格已用 | 展示已领；免费套装可返回既有领取结果；重复到访仍可零奖励记录 |
| `POOL_LOCKED` / `POOL_COMPLETE` | 未到访解锁／无候选 | 去关联点位／看其他卡池；不扣次 |
| `INSUFFICIENT_BALANCE` | 有候选但次数不足 | 展示未领奖机会及模拟购买，不推荐已领取点位再次获次 |
| `LOOK_INVALID` | 未拥有、槽位错误或素材不适配 | 保留草稿并指出限制，不偷偷发物或替换 |
| `STALE_PREVIEW` / `REVISION_CONFLICT` | 输入、账号或版本变化 | 不保存旧结果，保留可用选择，刷新或重新生成 |
| `STORAGE_UNAVAILABLE` / `DATA_INVALID` | 写入失败或结构损坏 | 保留原存档、不宣称成功，提供重试与恢复说明 |
| `RENDER_FAILED` / `REQUEST_CONFLICT` | 合成失败／请求 ID 复用冲突 | 恢复控制状态；前者可重试，后者核对原操作结果 |

错误码为新适配层目标，现有中文错误不能被文档误写为已有机器码。验收方法见[测试与发布验收](测试与发布验收.md)。

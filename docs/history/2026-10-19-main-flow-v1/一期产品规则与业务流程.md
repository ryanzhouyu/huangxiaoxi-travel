# 黄晓西换装体验一期产品规则与业务流程

版本：主线确认版 v0.2，子环节继续讨论。更新日期：2026年10月19日。

目标是在本周内完成可部署、可实际操作的最小体验版，用测试景区与测试点位验证“获得数字伙伴 → 领取景区套装 → 体验打卡 → 获得抽奖次数 → 免费或付费流程抽取部件 → 换装 → 留下旅行回忆”的完整业务。视觉、人物美学和动效可以逐步完善，业务状态应正确保存并可追溯。

本文将用户已确认内容与待讨论方案分别列明。当前阶段先完善业务与操作细节，确认后再划分产品模块与实施计划。

## 一 已确认的目标与范围

| 编号 | 已确认规则 |
| --- | --- |
| C01 | 换装主体为游客拥有的黄晓西数字伙伴，代表游客承载旅行回忆；游客无需上传本人形象。 |
| C02 | 伙伴脸部身份固定，发型、妆容、服饰可通过收集的虚拟装扮替换。 |
| C03 | 首次打开可从几个初始形象模板中选择喜欢的版本。具体模板数量和可更换范围尚未确定。 |
| C04 | 游客在线上查看景区时，可免费获得该景区的默认套装，以新手引导体验换装。 |

| C06 | 景点路线引导、商家分流和景区活动参与属于这条主线的一部分。 |
| C07 | 收集、换装与到访经历进入回忆及线上纪念图片，数字伙伴作为画面主体。 |
| C08 | 宠物养成留到长线版本，一期先聚焦打卡、收集、换装和回忆。 |
| C09 | 本周验收采用可部署体验版和测试点位，无需以真实景区现场接入作为完成条件。 |
| C10 | 一期包含付费购买抽奖次数的流程；无需接真实支付，可演示支付与购买结果。 |
| C11 | 套装在景区内配置；卡池可组合若干套装，并按运营需求关联景点。不同景点可使用不同卡池，也可共享同一个卡池。 |
| C12 | 抽奖次数在同一景区内通用，可在多个景点打卡积累后选择其他景点的卡池使用。购买次数也按此景区范围展示和发放。 |
| C13 | 首次有效到访卡池关联景点后解锁该卡池，之后可随时抽取；共享卡池到访任一关联景点即可解锁。免费与购买次数遵守相同的卡池解锁条件。 |
| C14 | 一期以单个景区的一次游玩组织旅程和回忆。 |
| C15 | 第一次有效打卡自动开始本次游玩，后续有效打卡归入该次尚未结束的游玩；线上领套装不算到访。 |
| C16 | 游玩中可随时生成回忆作品；游客主动结束本次游玩后，生成完整总结。 |
| C17 | 一期交付回忆记录与静态纪念图片，可保存或分享；视频生成和实体纪念品下单留到后续。 |

已确认主线见 [主线业务流程图](主线业务流程图.md)。接下来按图中阶段逐项确认子流程，不因主线确认而将本文中的细节建议自动定为规则。

用户本轮称呼为“黄晓西”，本文采用此写法。历史画板、素材文件及工作目录保留“黄小西”原名。

## 三 游客业务流程草案

### 首次进入和选择伙伴

游客第一次进入，看到若干初始形象模板。每个模板展示同一个黄晓西身份下的初始搭配，选择后预览并确认，进入伙伴首页。将模板理解为搭配而非不同身份，是根据固定脸部要求提出的方案。

建议初始搭配保持完整，后续更换单个部件也不会出现缺失服饰的状态。更换初始模板的入口、是否支持昵称，以及如何接账号，留待操作流程确认。回访游客直接恢复已保存的伙伴和进度。

### 在线查看景区和领取免费套装

游客进入景区详情，先了解可游玩内容，再看到“领取景区体验套装”。点击后发放整套装扮，并提供“立即试穿”。完成试穿后，展示变化以及继续探索的入口。

建议每个账号对每个景区免费领取一次；重复进入显示“已领取”，可再次试穿，但不重复发放。免费套装与当前穿搭分别保存，领取不会强制覆盖原搭配。

**线上领取只记录获得装扮，不记录实地到访。** 未到现场的游客可体验换装和预览纪念图；真实到访路线只由核验后的事件组成。预览作品标明预览，不计入到访记录。

### 看路线和选择任务

游客看到景区内的推荐游玩顺序、景点、商家与活动任务。每项应明确说明地点、参与条件、可获得的奖励、有效时间及当前完成状态。路线作为推荐，不强制按顺序完成。

点击任务详情后，提供前往地点或参与说明，并预览关联装扮。商家到店与活动完成分别说明要求；仅浏览详情不算完成。测试版用测试地点与说明验证这些步骤，正式定位及导航接入范围后定。

### 完成打卡或活动

游客主动点击扫码、定位验证或活动验证，看到明确的成功、失败或待核验反馈。核验成功后，记录一次有效参与并发放抽奖次数，显示所属景区、增加数量及可用余额，提供“现在抽”和“继续游玩”。

建议任务可配置扫码、定位、活动凭证等核验方式，实际支持哪些方式按试点收敛。测试环境可以模拟核验，但模拟结果须保留来源，不能只在界面上提示成功而没有参与记录。

建议同一任务在其配置的参与周期内只奖励一次。重复扫码、定位重试或刷新返回已完成结果；到访记录和奖励记录建立关联。弱网时明确告知“核验中”或“尚未成功”，恢复后先查结果再重试。

### 查看卡池和抽取部件

进入卡池，游客先看到奖励、已拥有部件、获得方式及抽取规则，再使用次数抽取。抽取成功即获得对应部件，展示名称、部位、所属套装和收集进度，提供“试穿”和“继续抽取”。

**已确认的组织关系：**景区维护套装目录；运营把指定套装组合成卡池，再把卡池关联到景点。A 点可以关联包含套装 1、2 的卡池，B、C 点可以共享包含套装 3、4 的另一卡池。共享表示使用同一份卡池配置，而非复制两份。景点与卡池不按固定一一关系写死。

**已确认的次数范围：**游客在该景区有统一的抽奖次数余额，从不同景点或活动获得的次数汇入这里；在任意符合抽取条件的卡池使用时，扣减同一余额。景点详情与卡池页都应显示“本景区通用次数”，并提供卡池所属景区信息。跨景区是否可转移并未提出，一期按各景区独立余额设计。

抽取结果确定后即计入资产，关闭结果弹窗不会丢失奖励；“试穿”仅改变搭配预览。刷新抽取中页面应能恢复已确定的结果，不能再次扣次或重新抽奖。

首次有效到访关联景点后解锁卡池；共享卡池到访任一关联景点即可解锁，之后可随时使用本景区次数抽取。是否重复、概率和抽空处理留到抽取子流程确认。原画板的不重复获取尚未作为本轮已确认规则。

### 模拟购买抽奖次数

游客可从次数不足提示或购买入口进入套餐页，确认购买数量、示例金额、所属景区及“模拟支付”标识，然后选择模拟支付成功或取消。购买的是本景区通用次数，不是某个景点或卡池的专用券。

建议只有模拟支付成功才发放次数；取消或失败保留订单状态且不增加余额。同一订单重复回调只发一次。游客能够看到订单和次数增加记录，购买成功返回原卡池。

为保证演示真实反映业务，模拟购买也走订单、支付状态和发放记录；次数的发放以服务端确认的模拟结果为准，不由前端直接修改余额。展示价格为测试配置，不代表正式定价。

### 换装与保存

游客在衣橱选择已拥有部件，实时预览搭配后保存。建议区分“正在预览”和“当前已保存”；同一部位互斥，未拥有部件可以预览，但不能保存为可用搭配。具体是否允许未拥有预览待确认。

返回首页后应看到已保存形象，刷新与重新进入保持一致。保存更换发型、妆容和服装时，伙伴的身份保持一致。服饰部位、上下装与连衣裙的互斥关系、搭配兼容规则，在资产样板确定时收敛。

### 查看回忆与生成纪念图

已确认第一次有效打卡后自动建立该景区的一次游玩记录，后续有效打卡归入该次尚未结束的游玩。游玩中可随时生成回忆，游客主动结束后生成完整总结。建议每个有效地点或活动成为一条记忆，保存时间、地点、体验内容、奖励来源及当时已保存的搭配版本。抽奖和换装可以关联为收获，不增加虚构的到访地点。

游客打开回忆，查看按时间排列的经历，选择一条记忆或整次游玩生成静态纪念图；可修改短句，选择当时形象或当前形象进行重新演绎。选择当前形象不会覆盖原到访快照。

一期已确认交付回忆记录与静态纪念图片，可保存或分享；视频与实体下单后置。建议使用稳定模板合成伙伴、背景、时间和地点；不把“点击分享”当成外部平台已发布。AI 文案与具体分享方式在作品子流程讨论。

## 四 关键记录和异常规则建议

| 业务 | 必须保持一致的结果 |
| --- | --- |
| 免费领取 | 一次领取对应唯一发放记录；重复点击不多领。 |
| 核验发奖 | 一次有效参与能追溯到任务、核验方式与奖励；重试不重复计次。 |
| 抽取 | 扣除次数、确定结果、发放部件作为一次完整操作；失败不出现只扣不发。 |
| 模拟购买 | 订单成功后发放；重复通知不重复入账；取消无奖励。 |
| 衣橱 | 资产拥有状态与当前搭配分开；保存仅使用满足规则的部件。 |
| 回忆 | 历史记录保存地点时间与搭配快照；后续换装不改写旧经历。 |
| 测试标记 | 测试点位、模拟核验和模拟支付可追溯；测试作品保留演示标识。 |
| 配置变化 | 任务下架不删除已有收获；卡池变更不改写历史结果；价格调整不改变已有订单金额。 |

测试版若允许重置账号进度，应提供单独的演示重置操作；正常领取和抽奖入口仍遵守去重规则。

## 五 后台需要支持的业务操作草案

先确定运营要做的动作，再决定用几个管理页面完成。

| 运营动作 | 需要维护或查询的内容 | 生效前检查 |
| --- | --- | --- |
| 配置景区 | 名称、介绍、背景、免费套装、游玩点位、测试标记 | 套装完整可用；图片来源和展示状态明确。 |
| 配置景点与路线 | 所属景区、位置、排序、推荐路线、点位说明 | 不把示意布局当作真实导航；点位可在测试流程中到达。 |
| 配置商家与活动 | 所属景区、参与条件、有效时间、核验办法、完成次数限制 | 游客能提前知道是否消费、如何参与及如何证明完成。 |
| 配置奖励任务 | 任务对应点位或活动、奖励次数、所属景区、领取周期 | 同一次参与不会因多个入口重复发奖；发放到正确的景区余额。 |
| 管理服饰资产 | 初始模板、脸部基底、部件、部位、套装、预览与合成素材、适配规则 | 脸部一致；缺失部位有默认装扮；层级和穿戴组合可用。 |
| 配置卡池 | 所属景区、包含的套装及部件、关联景点、抽取规则、开放状态 | 套装属于正确景区；共享点位引用同一配置；奖品可穿戴；概率与实际一致。 |
| 配置购买套餐 | 所属景区、次数、示例价格、模拟支付标记 | 明确景区通用范围；从卡池购买时先检查该池可抽状态，并提示其他可用卡池。 |
| 查询与处理异常 | 用户资产、参与核验、次数收支、抽取结果、模拟订单、纪念作品 | 同一笔业务可关联查询；补发需填写原因并留下操作记录。 |
| 配置回忆模板 | 地点背景、文字区、伙伴区域、时间与路线展示 | 地点信息与事件一致；输出文字和演示标记可读。 |

不建议首期开放无限自由的规则编辑器。可先使用固定几种任务和奖励类型，通过配置组合；后续按真实运营需求扩展。

## 六 待确认的业务选择

| 优先级 | 待确认问题 | 建议起点 |
| --- | --- | --- |
| 优先 | 服饰是否不重复抽取？抽空后剩余次数如何处理？ | 不重复获得，抽取前展示剩余内容；抽空卡池不可再扣次，剩余次数继续用于本景区其他可抽卡池。 |
| 优先 | 游客再次进入同一景区，是继续上次游玩还是开启新旅程？重复到访是否再次给抽奖次数？ | 资产长期保留，游玩记录按旅程区分；重复到访奖励单独按任务周期控制。 |
| 随流程确认 | 免费套装是否每景区每账号一次，领取与穿戴是否分开？ | 领取一次，可重复试穿；两个状态分开。 |
| 随流程确认 | 初始模板是否只改变搭配，是否允许后续自由切换？ | 同一个脸部身份、完整初始搭配，可在衣橱调整。 |
| 随流程确认 | 第一次抽取是否提供引导奖励或保证立即可用？ | 初始与免费套装已经完整可穿；抽到单个部件后可直接试穿。 |
| 接口前确认 | 体验版如何识别账号、从主应用进入；是否已有角色素材与服务？ | 先核实已有资源，不提前承诺重新建设账号或角色引擎。 |

## 七 本周样板验收建议

| 场景 | 应观察到的结果 |
| --- | --- |
| 新游客进入 | 选初始模板后得到完整伙伴形象，刷新仍存在。 |
| 线上领取 | 领取景区默认套装并试穿；重复领取不增加资产，未记录现场到访。 |
| 完成测试任务 | 能验证成功、失败、重复操作三种情况；只在有效完成时增加次数。 |
| 免费抽取 | 余额扣减与部件发放一致，结果可查，关闭或刷新不丢失。 |
| 景区内通用 | 在 B 点获得次数后可用于 A 点的可用卡池；两处显示同一景区余额。B、C 共享卡池的奖励配置保持一致。 |
| 模拟购买 | 取消不加次数，成功加次数，重复确认不重复发放；全程标明模拟。 |
| 换装保存 | 同部位切换正确，保存后首页及刷新显示一致。 |
| 生成回忆 | 展示正确测试地点时间与伙伴形象，能生成并保存静态图片；后来换装不覆盖旧快照。 |
| 运营维护 | 修改测试任务、卡池或套餐后新操作使用新配置，历史资产与结果保持可追溯。 |

只有上述范围与业务规则收敛后，再估算具体页面、服务、素材量和开发顺序。一周内完成的主要约束是账号／宿主环境、角色素材可用性及规则复杂度，目前尚不能将完整功能清单视为已排期承诺。

# 黄晓西游客端页面模块与初始化范围

版本：结构方案 v0.1，后续展开见 [完整体验与验收标准 v0.3](../../完整体验与验收标准.md)。更新日期：2026年10月19日。依据原画板、已确认 [产品规则](../../一期产品规则与业务流程.md) 及 [竞品研究](../../../research/2026-10-19-competitors/换装游戏界面参考.md)。此处保留最初模块划分，当前实际页面与交互以 v0.3 为准。

**最初重心为页面框架、功能模块与初始化，现已展开为完整交互体验。** 素材制作方式、人物母版、精确部件清单与素材数量继续后置。v0.1 采用文字占位，v0.2 已采用可替换部件示意及实际 PNG 合成，不以角色美学完成度作为前置条件。

## 一 总体结构

v0.3 当前实施方案将主要场景入口收敛为“伙伴、游玩、回忆”。衣橱从伙伴侧边背包、获得装扮或纪念图制作进入，作为专注的试衣界面，保存返回来源；不在底部重复放置。下表仍按功能模块列示，模块不等同于一级入口。图鉴属于衣橱内的收集视图。完整 AI 对话、宠物、好友、长期养成、商城与运营管理页面不加入本期。

| 入口 | 核心问题 | 主要内容 |
| --- | --- | --- |
| 伙伴 | 我的伙伴现在是什么样，还能做什么？ | 当前保存搭配的预览位、所选景区、换装、查看游玩与回忆入口。 |
| 游玩 | 这个景区有什么可以体验和获得？ | 景区列表、详情、辅助点位导览、商家与活动、打卡和卡池入口。 |
| 衣橱 | 已有什么，怎么搭配，还差什么？ | 搭配编辑、部件与表情姿势分类、套装图鉴、缺件来源。 |
| 回忆 | 去过哪里，如何做成纪念？ | 实际足迹时间轴、日期范围、作品列表、纪念图制作与详情。 |

主页面使用稳定导航；点位、套装、卡池、作品详情用返回导航；衣橱编辑与纪念图制作允许更大的工作区。每个页面保留所属景区与来源上下文，禁止因跨页修改搭配而清空正在制作的回忆范围。

## 二 页面清单

共建议13个页面类型及6类可复用弹层。数量按页面职责计算，不等于13种独立布局，也不要求一周内完成全部视觉和业务联调。

| 编号 | 页面与建议路径 | 页面职责与主要区域 | 原画板依据 |
| --- | --- | --- | --- |
| P01 | 演示账号入口 /entry | 进入或切换演示账号、恢复进度、携带扫码回跳目标。 | 原启动页承担进入功能，真实账号接入已后置。 |
| P02 | 初始伙伴 /onboarding | 初始模板预览、选择与确认；全部初始装扮免费。 | 029／030。 |
| P03 | 伙伴首页 /partner | 伙伴预览位、当前景区与进度摘要、去游玩／换装／回忆入口。 | 009，去除宠物与好友入口。 |
| P04 | 景区浏览 /explore | 景区选择、免费体验状态、已有足迹提示；当前测试数据可只有一个景区。 | 016／017，省域和景区选择先合并。 |
| P05 | 景区详情与导览 /scenes/:sceneId | 介绍、默认免费套装、点位地图或列表、景点／商家／活动筛选、奖励预告。无需先选择路线任务。 | 001／017／072。 |
| P06 | 点位详情 /points/:pointId | 入口、景点、商家共用基础模板，按类型展示介绍、核验、奖励资格、关联卡池和活动。 | 002／040／006／043。 |
| P07 | 活动详情 /activities/:activityId | 条件与奖励、与到店奖励的区别、模拟店员核验；回到来源商家。 | 006动作彩蛋扩展为明确的活动条件。 |
| P08 | 卡池 /pools/:poolId | 景区通用次数、锁定／可抽／收齐状态、奖励与套装、等概率说明、抽取入口。 | 012／004／005。 |
| P09 | 衣橱 /wardrobe | 搭配／图鉴视图；角色预览位、配置化分类与网格、已拥有／穿戴／预览状态、保存。 | 007／008／067／070／071。 |
| P10 | 套装详情 /collections/:outfitId | 整套预览位、部件持有进度、缺件和来源；已拥有完整套装可应用。 | 070／071。 |
| P11 | 回忆 /memories | 足迹／作品视图，景区与日期范围、时间轴、作品入口；无打卡为空状态。 | 044／045。 |
| P12 | 纪念图制作 /memories/compose | 已选真实经历、模板、当前搭配预览位、换装回跳、作品预览与保存入口。 | 003／044／045的生成入口展开。 |
| P13 | 作品详情 /works/:workId | 已保存作品、来源经历和日期、保存图片、再次制作；原作品不随换装变化。 | 003分享页与回忆图册。 |

## 三 弹层与组件

| 弹层 | 使用位置 | 处理结果 |
| --- | --- | --- |
| O01 套装领取结果 | 景区默认套装 | 已领取／新领取；立即试穿或留在原景区。 |
| O02 打卡／活动结果 | 点位与活动 | 本次经历、次数变化、卡池解锁、已领状态；去抽取或继续游玩。 |
| O03 抽取结果 | 卡池 | 奖品类型与拥有状态；去试穿或留在原池。中奖在服务端确定后即拥有。 |
| O04 购买次数 | 卡池余额入口 | 套餐、所属景区、模拟支付成功／取消／失败；返回原池。 |
| O05 足迹事件详情 | 回忆时间轴 | 真实事件、核验来源、所获奖励、加入当前制作范围。 |
| O06 未保存变更确认 | 衣橱及制作过程 | 保存、放弃或继续编辑；不能静默丢失搭配或经历选择。 |

共用组件包括导航、景区上下文、状态提示、次数余额、资产卡片、套装进度、来源说明、点位列表、时间轴、预览容器和空／错／加载状态。素材预览组件只要求明确输入输出与占位显示，不在此轮固定渲染技术或素材生产方式。

## 四 关键跨页闭环

1. 现场扫码 → P06；若账号或伙伴未建立，P01／P02完成后回到原点位，不强制回到线上景区浏览。
2. P05领取默认套装 → O01 → P09试穿；保存后可回到原景区。
3. P06／P07核验 → O02 → P08；共享卡池显示同一池状态，余额始终是当前景区通用次数。
4. P08抽中 → O03 → P09，并定位新部件／表情／姿势；保存后可返回原池。
5. P09图鉴 → P10缺件 → 来源点位或卡池；已解锁去抽，未解锁先显示到访条件。
6. P11选择已有经历 → P12 → 去P09换装 → 保存回P12，保留日期、经历集合和模板，再生成P13。
7. P13再次制作新作品 → P12；既有作品文件和来源信息不被覆盖。

以上是自由入口与回跳关系，不新增主流程中的选任务、手动开始或结束动作。拥有经历后，可以跨天反复出图。

## 五 功能模块与能力边界

| 模块 | 负责的状态与能力 | 初始化交付 | 后续业务实现 |
| --- | --- | --- | --- |
| M01 入口与会话 | 演示账号、伙伴是否建立、回跳上下文 | 路由守卫、演示身份适配接口、持久化边界定义。 | 服务端身份与账号隔离、恢复进度。 |
| M02 景区与点位目录 | 景区、点位、商家、活动、卡池关联 | 固定配置模型、页面查询接口、加载错误与空状态。 | 点位二维码解析、真实查询与开放状态校验。 |
| M03 到访与领奖 | 事件、首领资格、解锁、景区次数增加 | 真实／模拟核验类型、结果结构、前端状态模板。 | 去重、自动记录、一次发奖与解锁一致性。 |
| M04 卡池与次数 | 解锁、跨池排重、等概率、账本、模拟订单 | 候选集合与订单接口契约、锁定／空池／余额等状态。 | 服务端抽取与扣次入库、模拟订单入账。 |
| M05 衣橱与收集 | 已拥有资产、当前穿搭、预览草稿、套装进度 | 配置化资产类型、编辑状态、素材预览适配接口。 | 持久化穿搭、适配校验、素材合成接入。 |
| M06 回忆与作品 | 事件范围、作品草稿、当前搭配快照、作品文件 | 时间轴、筛选、制作上下文、模板与导出接口。 | 数据查询、静态图合成与文件保存。 |
| M07 公共界面与配置 | 导航、反馈、弹层、格式化、测试配置 | 共用组件、设计变量、示例状态与开发说明。 | 按业务接入请求结果，不承担独立余额或奖励真相。 |

前端不以本地按钮修改余额代替业务结算；初始化模拟适配器与后续真实服务有明确边界。固定配置不等于不需要持久化的业务服务。

## 六 初始化验收与后续顺序

最初交付为竞品参考、页面／模块／能力拆分和 [v0.1 结构草案](../../../design/archive/v0.1/index.html)。该历史草案只演示区域、状态和跳转。当前入口已升级为 [v0.3 游玩交互体验](../../../design/index.html?v=3#partner)，支持本地进度、测试码核验、抽取和实际 PNG 合成，尚未接云端及真实业务服务。

接下来工程初始化的验收应为：项目能本地运行和构建；页面路由及公共布局齐全；13类页面通过模板组合承接；六类弹层有对应状态；固定配置与用户状态分离；各模块接口输入输出确定；未到访、已到访、收齐与异常有可检查的页面样例；换装与制作回跳保留上下文。

初始化完成不表示业务联调完成。随后优先接入口与伙伴 → 景区与核验 → 次数和抽取 → 衣橱保存 → 回忆与作品。素材只预留清单、预览容器和替换接口，制作方案、获取方式、数量与预算下一轮讨论。工程技术栈在实际初始化时选定，不把本轮HTML结构草案当作既定产品技术栈。

| 工程初始化顺序 | 具体产出 | 检查方式 |
| --- | --- | --- |
| I01 应用骨架与公共布局 | 启动／构建配置、路由、一级导航、返回策略、公共弹层和状态提示。 | 本地可启动可构建；手机与桌面能访问，无横向溢出。 |
| I02 页面模板 | 13个职责入口由共享详情、列表、编辑、结果模板组合；6类弹层。 | 目录全覆盖，加载／空／异常状态可预览，不做不可解释的空白页。 |
| I03 模块契约与测试配置 | 账号、景区、点位、活动、卡池、奖励、资产、穿搭、事件、作品、订单的数据关系。 | 点位与卡池可共享，次数按景区归属；固定配置与账号状态分离。 |
| I04 页面状态与上下文 | 模拟适配器、衣橱草稿、回跳目标、纪念图经历范围与模板状态。 | 新游客、已有足迹、未解锁、已收齐、异常均可检查；换装回跳不丢选择。 |
| I05 能力边界 | 为核验、抽取、订单、保存搭配、预览、合成与文件保存预留接口；未接入明确标记。 | 界面结构预览不被当作已执行真实支付、核验、抽取或出图。 |
| I06 初始化验收 | 构建结果、关键导航检查、部署入口和已完成／未接入清单。 | 结构初始化与业务联调的验收记录分开；素材不作为此阶段阻塞。 |

上表为最初的初始化安排。当前具体实现与验收转到 [完整体验与验收标准](../../完整体验与验收标准.md)；采用原生 ES modules，无需打包构建，业务处理暂由浏览器本地适配器承接。

当前优先完成无正式素材也能完整操作的原型；真实素材与最终视觉效果在后续阶段验收。原有业务规则作为后续服务端实现目标继续保留。

# 黄晓西换装体验子环节功能实施说明

更新日期：2026-10-19。状态：六个子环节的业务职责说明。依据 13 张讨论卡片及[当前产品规则](一期产品规则与业务流程.md)，主线[流程图 v2](主线业务流程图.md)不变。逐页交互统一见[交互规格](完整体验与验收标准.md)，本文件不重复维护页面版本。

一期功能目标为独立手机网页游客端、演示账号保存进度、测试二维码实际可用，以及定位、店员活动核验和支付明确模拟。当前已从框架推进到 [完整本地交互体验](完整体验与验收标准.md)，可替换部件示意及 PNG 合成用于验证流程；正式素材与服务接入继续后置。本说明保留后续完整业务服务实现目标。

以下“已确认”来自用户回答，“默认方案”用于收敛实现，仍可在模块设计时调整。技术上必须保证的数据一致性直接落实，不另设讨论卡片。

## 01 入口与数字伙伴

已确认：所有初始装扮免费可用，首次模板选择仅决定当前默认搭配；角色脸部身份固定。首期使用静态、可替换素材。

默认流程：演示账号进入 → 首次选择模板并确认 → 保存伙伴及默认搭配 → 浏览景区；回访直接恢复。扫码首次进入时保留原点位，完成必要的伙伴建立后返回该点，不强制先走线上领装。

| 功能责任 | 实现要求 |
| --- | --- |
| 游客操作 | 看初始模板、预览、确认；回访恢复；在衣橱调整已有初始搭配。 |
| 系统处理 | 为账号建立伙伴并持有全部初始免费资产；首次选择改变穿戴，不限制其他初始资产。 |
| 保存内容 | 演示账号、伙伴、已拥有资产、当前保存搭配。 |
| 固定配置 | 脸部基底、初始资产目录、模板与部件关联、合成顺序。 |
| 验收 | 账号 A 换装后刷新仍在；账号 B 不继承 A 的增量资产、余额与回忆；首页和纪念图的伙伴搭配一致。 |

详见 [入口与数字伙伴子流程](01入口与数字伙伴.md)。具体模板数量和账号进入样式由模块方案给出。

## 02 景区浏览与免费体验套装

已确认：在线浏览景区即可获得对应默认免费套装，帮助体验换装；不产生实地到访记录。

默认流程：浏览景区 → 主动领取体验套装 → 查看获得结果 → 可试穿并保存，也可继续浏览。每个账号每个景区领取一次；套装为资产组合，重复进入可再穿，不重复发资产。

| 功能责任 | 实现要求 |
| --- | --- |
| 游客操作 | 查看景区介绍、套装与体验说明；领取、试穿、保存。 |
| 系统处理 | 检查是否已领，发放套装全部部件；领取与当前穿戴分开，不直接覆盖已保存搭配。 |
| 保存内容 | 景区免费领取记录、发放的资产、另行保存的穿搭状态。 |
| 固定配置 | 景区、介绍与背景、默认套装、关联点位、奖励预告。 |
| 验收 | 重复点击只领一次；资产可穿；仅线上领装时没有真实足迹或实际到访回忆。 |

免费套装无需地点核验，抽奖卡池仍遵守到访解锁条件。不能用购买次数或免费领装绕过卡池解锁。

## 03 实地游玩与打卡

已确认：测试二维码实际可用，定位与活动核验模拟；普通入口、景点每账号首次到访才发次数。商家到店和每项活动分别每账号奖励一次，活动完成在业务上需店员核验。

默认流程：手机扫码打开点位 → 查看并确认打卡 → 系统核验 → 记录经历、发放可领取次数、解锁关联卡池 → 查看结果，可继续游玩或抽取。活动页以明确的演示入口模拟店员核验成功／失败，无需另做店员管理页面。

| 对象 | 业务条件 | 奖励资格 |
| --- | --- | --- |
| 景区入口或景点 | 对应二维码成功核验；定位入口本周模拟。 | 账号在该点首次有效到访一次。 |
| 商家到店 | 对应商家到店码核验成功。 | 每账号每商家的到店奖励一次。 |
| 消费／体验活动 | 对应活动完成，经过店员核验；本周模拟结果。 | 每账号每项活动一次，与到店奖励分开。 |

| 功能责任 | 实现要求 |
| --- | --- |
| 系统处理 | 区分到访是否记录、奖励是否已领、哪些卡池可解锁。共享卡池到访任一关联点即可解锁。 |
| 保存内容 | 参与事件、时间地点、核验方式、模拟标记、领奖记录、次数增加记录、卡池解锁记录。 |
| 固定配置 | 点位码、点位类型、活动条件、奖励次数、关联卡池、开放状态。 |
| 验收 | 首次到访入账，重试不多发；后续真实到访可以留记忆，已领资格不复位；活动失败不发活动奖励；到店成功不等于完成消费。 |

同一次操作的重试只保留一次结果。后续重新到访如何形成新事件，由核验请求与确认交互设计处理，不把每次刷新页面当作新经历。

## 04 抽取与模拟购买

已确认：次数景区内通用；地点卡池可共享；排除账号已拥有的所有奖励，跨卡池也排除；剩余奖品等概率。模拟支付成功才发放购买次数。

默认流程：进入已解锁卡池 → 看到剩余可抽内容和景区余额 → 单次抽取 → 自动入库 → 查看结果，可去装扮或继续。次数不足可返回游玩获得，也可选模拟购买。首期建议先保证单抽完整，套餐可购买多次余额；连抽按钮不作为核心前置。

**可抽集合 = 当前卡池有效奖励 − 账号已拥有资产。** 服饰、表情与姿势均使用统一资产标识；同一奖励不能因复制卡池而变成两件不同资产。

| 情况 | 系统行为 |
| --- | --- |
| 卡池未解锁 | 展示到访条件，不允许抽取；购买次数也不能解锁。 |
| 可抽集合为空 | 显示已收齐，不扣次数，不误提示余额不足；其他池仍按各自状态使用余额。 |
| 余额充足 | 确定一个未拥有奖励，同时扣一次、入库并保存结果；结果弹窗关闭不影响拥有。 |
| 模拟购买取消／失败 | 不增加余额，保留相应订单状态。 |
| 模拟购买成功 | 按订单对应景区和套餐入账一次，返回原卡池；重复通知不多发。 |
| 请求超时后重试 | 查询原请求结果，不重新扣次或重抽。 |

保存次数收支、抽取结果、统一资产拥有记录和模拟订单。固定配置包含奖池、奖励关联、套餐次数与示例价格；首期不做权重配置。示例套餐与金额由测试配置给出，不代表正式定价。

验收时用两个共享／重叠奖池证明跨池排重、余额通用、收齐不扣次、模拟购买幂等，以及抽中后刷新仍持有。等概率的算法与候选集合可检查，不用少量演示抽样宣称概率已得到统计验证。

## 05 衣橱与伙伴装扮

已确认：简化可替换素材、固定脸部身份、静态姿势与表情；首页和纪念图一致使用。未要求接入人物引擎或播放动画。

默认流程：打开衣橱 → 选择已拥有部件／表情／姿势 → 预览 → 保存 → 首页更新。预览与保存分开；取消不改当前保存搭配。同部位互斥，保存使用已拥有且适配的资产。

| 功能责任 | 实现要求 |
| --- | --- |
| 资产配置 | 明确类型、部位、图片、合成顺序、坐标及兼容姿势；服装部件可独立获得和替换。 |
| 合成规则 | 脸部身份稳定；发型、妆容／表情、服饰、姿势按照配置组合；不能把整张原型图切换当作真实部件替换。 |
| 保存内容 | 当前搭配引用的资产与姿势、保存版本。 |
| 素材范围 | 使用有限的可验证组合，具体部位和数量在素材清单中锁定；不承诺任意服装适配任意姿势。 |
| 验收 | 换一件部件能保留其他部件；刷新恢复；未适配组合给出明确限制；首页、衣橱与出图一致。 |

未拥有资产的展示可以在图鉴或卡池预览，不在保存时偷偷发放；是否提供自由试穿属于可逆界面方案，先以已拥有资产操作完成闭环。

## 06 回忆生成与分享

已确认：至少一次有效实地打卡才有真实回忆；按景区持续记录，支持多天；无开始／结束操作。固定模板合成，使用当前保存搭配，旧作品不随之后换装改变。

默认流程：打开已有景区回忆 → 选择单条、当天或日期范围 → 查看足迹与收获 → 以当前伙伴搭配生成 → 预览 → 保存图片；已有记录可反复使用。具体筛选控件与模板数量由页面方案决定。

| 功能责任 | 实现要求 |
| --- | --- |
| 内容来源 | 地点、时间和体验来自参与记录；伙伴来自当前保存搭配；背景来自固定景点素材配置。 |
| 足迹与路线 | 按有效到访顺序展示已到点位，不把未到点位补为经历，不把点位连线宣称为完整 GPS 行走轨迹。 |
| 模板合成 | 支持角色、背景、地点时间和足迹信息；静态表情与姿势也按当前搭配应用。 |
| 保存内容 | 选择的经历集合、日期范围、生成时搭配与素材版本、模板版本、输出图片。 |
| 模拟标识 | 演示景区、测试核验或模拟事件在测试回忆中保留明确标识。 |
| 验收 | 线上领装或只购买没有到访回忆；一次打卡可出图，多天可合成；换装后新图变化，旧图不变；保存的文件可打开阅读。 |

本周以可保存静态图片完成分享基础能力；系统分享能力按运行环境适配，不把打开分享入口当作外部平台已发布。

## 配置与功能分工

已确认本周无后台管理页面。景区、点位二维码、活动、奖励、套装、卡池及套餐放在集中测试配置中，保持稳定标识；用户拥有、余额、打卡、解锁、订单、穿搭与作品属于需要持久化的业务状态。

固定测试配置不意味着把余额和抽取结果交给前端随意修改。实际发奖、扣次和模拟订单入账应由统一业务处理完成，并能通过测试查看记录。真实支付、真实店员登录、运营配置编辑和补发界面留到后续。

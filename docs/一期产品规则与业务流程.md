## 游客业务流程

1. **进入与伙伴。** 新账号选择初始默认搭配，全部初始资产入库；回访恢复。直接扫码首次进入时完成必要账号／伙伴步骤后回原点位，不强制补走线上领装。
2. **线上认识景区。** 浏览景区并主动领取免费套装，可试穿也可先收好。领取不自动穿戴、不算到访；免费套装不是实地打卡前置条件。
3. **实地游玩。** 到入口、景点、商家或活动后主动核验。有效核验一次完成经历记录、按资格发次和解锁；普通到访、商家到店与活动完成分别判断。路线推荐是辅助，不是任务领取步骤。
4. **抽取与模拟购买。** 使用景区通用次数；先验证池和解锁，排除已拥有资产，在剩余候选中等概率单抽。可多次打卡后再抽，也可离开现场后抽。次数不足展示仍可领奖来源或模拟购买；购买不解锁池。
5. **换装保存。** 在衣橱试穿已拥有部件，保存后更新正式搭配；取消不改变。获得与穿戴、草稿与正式状态分开，保存或放弃后返回来源。
6. **回忆制作。** 至少一条有效到访即可按单条、当天或多日范围制作。使用当前保存搭配与固定模板，保存独立 PNG 及经历快照；无需重新抽奖、换装、收齐或结束旅程。分享入口不等于已发到社交平台。

图示见[主线业务流程图](主线业务流程图.md)。页面和异常细节统一在[完整体验与验收标准](完整体验与验收标准.md)，不在这里重复按钮清单。

## 实施默认值与保护要求

以下为已采用的原型实施方案，不等同于正式运营规则或新增用户确认项。

| 项目 | 当前默认值 | 变更边界 |
| --- | --- | --- |
| 测试规模 | 一个景区、四点、一项活动、两池、三套初始搭配 | 数量可配置；不凭单场景结构声称已支持多景区 |
| 景区套装 | 每账号每景区领取一次，发部件，不自动穿戴 | 再次试穿不重复发放 |
| 搭配 | 七槽位；单部位互斥；只保存已拥有且兼容资产 | 连衣裙／妆容等新增槽位先补模型，不宣称已实现 |
| 抽取 | 单抽一次消耗一次；套餐可购买多个次数 | 不自动加入连抽、稀有度、保底或付费差异概率 |
| 重复到访 | 同点同方式 60 秒内防连续误点 | 只是演示防重，不是奖励周期或正式到访频次规则 |
| 模拟订单 | 仅 pending 可完成模拟；终态不重开 | 失败需新订单，旧单与旧价格保留；sourcePool 只供回跳 |
| 作品 | 两个模板；标题最长 16 字；保存固定图片 | 尺寸、样例套餐与测试价格见体验规格，不当作最终配置 |

业务一致性必须落实：初始化／领装／首次资格不重复发放；打卡结果成组提交；抽取扣次与入库同成同败；订单成功一次到账；历史事件及作品不因配置下架或换装被改写。当前本地提交保护有局限，目标契约和迁移要求见[数据模型与业务接口契约](数据模型与业务接口契约.md)。

## 当前阶段的补充确认

用户要求基于现有交互和原画板风格完成各页面高保真稿，并确认包含正式登录与账号绑定设计，服务接入后置。现有演示账号继续用于旧原型验证；正式登录渠道、手机号必需性、绑定冲突／恢复策略仍为设计草案，不能据此声称正式账号服务已定型。

角色动作、互动、换装素材组织与渲染路线需在对应正式实现前验证。高保真图中使用的角色和场景是概念示意，不自动成为生产素材或引擎选择。

## 待讨论与暂缓事项

| 事项 | 何时需要决定 | 当前保持 |
| --- | --- | --- |
| 全部池收齐后剩余次数的后续用途 | 改次数政策或新增运营规则前 | 保留余额，收齐池不继续扣次，不新增有效期／兑换／退款 |
| 地图点位摘要面板 | 确定进行该体验优化前 | 保留当前点位→详情的结构，不阻塞模块化 |
| 真实账号、云端环境与本地数据导入 | 服务接入阶段前 | 先保护本地进度；不假定平台、身份或部署地址已定 |
| 正式角色与素材 | 素材接入前 | 先准备[渲染接口](素材与渲染接口规范.md)，不启动批量素材生产 |

## 验收入口

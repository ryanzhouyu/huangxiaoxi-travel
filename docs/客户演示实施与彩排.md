## 两轮审查记录

第一轮沿真实入口执行登录、地图、抽取、换装、订单和下载。补上按地点显示的核验页、专属存储与会话、订单详情和刷新恢复；旧回归脚本原先限定 10 月，已改为按浏览器当天日期查询。独立验证脚本中还有两个等待问题，分别改为等待资源加载完成、按固定事件 ID 取消勾选，复测通过。

第二轮检查观众能看到的反馈及点击距离。将图鉴的服饰进度与全池进度分列，按资产归属显示表情、姿势、背景，修复背景 ID 与套装同前缀导致漏列的问题；将衣橱缩略图换成当前衣料局部；到店成功后直接进入手作；卡池提供继续游玩和翻开手账入口。投屏采用随窗口高度布局，三个主要入口可见。直接打开并检查了手机、桌面截图及实际导出 PNG。[桌面首页](../output/demo-rehearsal/投屏伙伴首页.png) · [小屏首页](../output/demo-rehearsal/伙伴-360x640.png) · [实际下载图片](../output/demo-rehearsal/旅行纪念.png)

## 现场使用边界

演示在本机测试景区和演示身份内运行。定位、店员确认和支付为显式模拟，正式账号、真实消费及云同步属于后续接入范围。记录中的秒数是自动化操作耗时。现场演示时可按讲稿留出说明时间。Windows 本机显示输出和有界面 Chrome 的核对记录见[实际显示彩排](../output/demo-rehearsal/external-display.json)。会场设备的接线、投影亮度和远处可读性须在到场后复核。

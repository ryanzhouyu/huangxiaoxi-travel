## 共用视觉规则

道具图标使用有填色和明暗的可编辑插画；返回、关闭等辅助符号保持简单清楚。纸面板采用单层细边、柔和投影和足够内距。操作和正文使用清楚的黑体，名称和少量标题保留宋体气质；正文以 14–16px 为主，辅助文字至少 12px，主要操作至少 44px 高。使用青绿色体现选中和主操作状态。桌面原尺寸阅览，通过滚动查看完整页面。

内容增长时优先设置明确滚动区，避免缩小字体或遮挡主要操作。各页面按自己的用途调整人物、画面和操作区比例，公共组件统一材质，页面布局按职责区别处理。

| 套装与部件 / outfit | 人物与套装标题建立主次，部件按可读宽度排三列，来源与搭配操作独立成区 | 七个部件文字、未拥有来源、衣橱与卡池去向 |
| 旅行手账 / memories | 保留手账结构，放大日期、足迹和来源；足迹区独立滚动，作品和空态统一材质 | 足迹／作品／无到访三状态，主导航、制作和作品入口 |
| 纪念图照相馆 / compose | 预览与编辑改为清楚的上下排布，避免文字压住作品日期；放大标题、模板和经历选择 | 调整搭配后保留输入，模板／经历选择，预览／失败／保存 |
| 作品与分享 / work | 让作品、标题与来源清楚分组，操作面板自然排列；统一保存与分享图标，保证小屏可滚动 | 保存／分享提示、旧作品说明、再制作去向 |
| 我的旅行身份 / account | 身份头像、账号和资料采用清楚字号；功能行统一图标和内距，退出保持次级操作 | 安全、次数、回忆、退出确认及取消 |
| 账号绑定与安全 / security | 填色手机与微信图标，放大绑定状态与恢复说明；更换与恢复弹层统一排版 | 更换、冲突、恢复和原绑定保护的文案与入口 |
| 次数与收支 / wallet | 余额、用途和购买分层；账本与订单采用统一行高、时间字号和正负数字颜色 | 两页签、购买套餐、订单入口及返回 |
| 模拟订单详情 / order | 状态插画与文本分层；商品、金额、编号和时间按可读网格排版，主次操作统一 | 待付／成功／失败／取消四状态，金额和返回来源 |

所有公共弹层同步调整：协议、隐私、微信说明、绑定冲突、领奖、地点列表、到访、抽取、次数不足、草稿保护、来源、制作失败、分享、退出、更换／恢复、购买、支付、店员核验、经历选择与定位模拟。按钮、输入及文字都必须位于可见或可滚动区域。

## 两轮独立审查

第一轮按全部页面和状态检查功能、阅读与布局。旧样式的强制字号导致若干协议错误、绑定说明和模拟提示仍为 10–11px，已统一修正。84 个失败断言来自多个视图重复检查，不是 84 个产品 bug；[首轮记录](../output/playwright/all-ui-review/round1.json)保留原始发现。

第二轮逐张查看全部 21 张默认稿及 39 张非默认／额外弹层图，并检查小屏操作：修正店内体验标题在深背景上的对比度、商家招牌与照片说明重叠、初次相遇重复说明遮挡、衣橱小屏已选区挤压部件状态，以及衣橱页签切换后选中态仍停在服饰的问题。最后看图又修正了切换表情／背景后预览说明仍写“头饰”的问题，并重新通过两种手机尺寸的 70 项串联检查。详情面板按内容收紧，长制作页和作品页保留自然滚动，避免压小字体或覆盖画面。订单终态采用统一状态徽章。

验收脚本另修正了横轴隐藏与纵轴可滚动的混淆，以及连续同 hash 查看弹层导致旧弹层未清除的问题；这些是测试隔离问题，没有作为产品缺陷数。最终检查采用独立视图地址和独立浏览器上下文，完整覆盖 240 个视图。

## 文件、运行与边界

`ui-system.css` 维护材质、字体、按钮、导航、弹层与桌面阅读；五个页面职责样式分别维护登录、游玩、衣橱、回忆和账号。`partner-art.mjs` 的填色道具插画经 `art.mjs` 在全稿复用，辅助返回／关闭保留清楚的方向符号；首页继续使用独立构图和局部样式。

`verify-all-ui.js` 和 `verify-ui-interactions.js` 可按[高保真 README](../design/hifi/README.md)中的 CLI 方式复验，分别读取 `window.hxxAllUIQA` 和 `window.hxxUIFlowQA`；执行退出成功不能代替提取并检查结果。当前阶段继续使用静态服务，无打包或新增运行依赖。

原业务原型的规则、存档、账号隔离与实际 PNG 合成保持原样，高保真稿仍是设计演示。真实身份、云端同步、支付、现场核验和角色素材／动作技术均未接入。浏览器检查使用独立上下文，没有清空或覆盖用户进度。

修改已保存在工作区。此前发现本机未设置 Git 作者身份，本轮没有代填身份、提交或推送；这不影响本地运行和本轮 UI 验收。

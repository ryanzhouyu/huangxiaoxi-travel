# 旅行衣橱验证设计

2026-11-18，针对游客原型 `731f0d4`，在独立入口做验证。资料先按[游客端设计资料取舍](游客端设计资料取舍.md)收口，现版衣橱及确认稿分别用于交互和画面对照。

## 要验证什么

继续沿用「工坊里看晓西换装」的构图。左边人物全身，右边是可独立翻阅的衣架。七个部位和保存操作放在同一张桌沿上。服饰图实际对应那一件，表情看脸、姿势看全身、背景看确切取景。保存过的穿着与当前试穿都用含义明确的文字标识。继续使用六套确认素材及原装扮 ID。

| 部位 | 做什么 | 验收条件 |
| --- | --- | --- |
| 舞台和边缘 | 工坊背景覆盖一整张工作台上方的画面，人物落在地面，避免因衣架变宽压成小头像 | 检查人物画布的实际不透明边界；脸、挥手、鞋尖、裙摆完整，人物和衣架不相盖，背景到桌沿无意外断层 |
| 衣架和部件 | 只显示拥有的同类部件；一件一个触点；图、名称和状态有同一读序；标出还能滚动的位置 | 360px 小屏及六件上装可看到并点到末项，切状态保留滚动和焦点；一件可用时仍讲清它是当前的选择 |
| 七部位与状态 | 七个类别恒定横排；清楚区分已保存穿着与正在试穿；其余可选不反复标「拥有」 | 同类切换只更新本部位；别的类保留草稿。当选中等于已保存时只用一个状态标识；分类与主要触区至少 44px 高且类别无截断 |
| 桌沿与返回 | 只在有改动时启用保存；恢复保持在衣橱；取消有保存、放弃、继续三个选择。图鉴查看再返回不会改搭配 | 360×640 可达全部主操作，模拟 30px 安全区后按钮仍完整；失败保留草稿；从制作进来的参数和勾选仍在 |
| 照相馆承接 | 独立样板带完整来源和制作输入，返回结果显示已保存搭配 | 试穿不会把未保存搭配带回来源；保存会返回同一来源及上下文；测试适配层不写游客演示键 |

验收样本包括现版默认、试穿及完整图鉴返回，以相同数据验证候选稿的默认、试穿、部位切换、衣架末项、取消选择、失败重试、恢复及制作来源。先核对实际动作和资产，再按 360×640、390×844、430×932、1280×720、1440×1000 分别看图，并模拟安全区。生产接口、真实动画、手机与微信真机另验。

## 已实现及验收

[可操作样板](http://127.0.0.1:8782/design/review/wardrobe-study/) · [截图对照](../output/wardrobe-study/2026-11-18/index.html) · [浏览器记录](../output/wardrobe-study/2026-11-18/checks.json)

- 工坊默认带人物与侧边衣架。侧栏由实际件数定高，装不下时衣架独立滚动。每件的边框、图、名称、状态都随内容占高。服装取原件，表情裁实际脸部，姿势用全身，背景用真实场景。切到背景类别时，舞台会切换到实际取景；其余类别回到工坊。
- 截图检查中修正了窄屏衣架行高压缩，以及保存失败后部分试穿标签被挤出衣架的问题。样板现在会把刚选中的部件完整移入视野，保留试穿状态和保存入口。
- Windows Chrome 157 使用隔离浏览器上下文完成六组检查，共截取 33 张原始图并归档其中 11 张。验证覆盖七部位默认、实际部件替换、六件上装末项、切换分类及图鉴往返、刷新草稿、取消和恢复、失败重试，以及伙伴、见面礼、卡池、照相馆的来源。五档视口的分类与主操作最小触区为 44×44 CSS 像素，人物不透明边界在舞台内。360×640 下模拟 30px 底部安全区，保存失败时底部操作仍完整可见，人物呈现高度约 273px。
- 现版游客原型另跑原有 23 项浏览器验收并实际导出 PNG。领域测试 14 项和文档检查均通过。
- 样板使用现有素材和保存规则，新增的试穿草稿留在单标签页的样板存储键。从当前样板返回来源时，展示保存结果和原制作上下文。该来源页是验证用的返回视图。实际游客衣橱入口仍是现版，正式接口、连续动画、iOS、Android 及微信内的实际安全区、滚动和性能待验。

复验见[运行说明](../design/review/README.md)。如迁入游客入口，应复用它现有的账户隔离、草稿、服务保存及路由处理，并重跑真实来源及返回路径。

用户随后指出人物与背景的层次、右侧选品与底部操作不协调。候选方案、竞品依据及后续复验见[衣橱竞品调研与视觉复验](衣橱竞品调研与视觉复验.md)。

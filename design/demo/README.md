## 明早开场

提前打开三栏台，左侧检查显示“本机素材与存档检查通过”后，点“进入全屏”。打开不会清空原有进度。需要从零演时，在“备份、载入与重新开场”里先备份，再点“重新开场…”并确认（影响本机 A、B 两份演示手账）。也可在中央选择尚未使用的身份。窄屏时，两侧收为顶部的“现场操作”和“游玩实况”。

用左侧“查看”介绍地点，用“模拟扫码”把该地点的码填进中央；此时停一下，让观众看到余额没变。只有在中央点“验证并记录到访”才记经历、发奖、解锁卡池。弹窗和处理中暂停地点切换；试穿未保存时，切地点会在中央询问如何处理。右侧是当前身份的实际记录，提示顺序不限制游客游览。

[三栏备用彩排（无声）](../../output/stage-rehearsal/三栏连续彩排.webm) · [录像中实际导出的纪念图](../../output/stage-rehearsal/三栏演示纪念.png) · [投屏截图](../../output/stage-rehearsal/三栏投屏.jpg)。也可点左侧“观看备用彩排”，播放、暂停和关闭均不改变现场手账。

| 现场操作 | 讲给客户听 | 核对点 |
| --- | --- | --- |
| 选新手账和初始搭配 | 这位是游客的数字伙伴黄晓西。游客用伙伴记录旅行，也能保留自己的真实形象隐私。 | 通用次数 0，尚无到访 |
| 游玩 → 黔山漫游 → 景区见面礼 → 试穿并保存 | 在线看景区就能收下这套装扮。试穿后由游客决定是否保存。 | 领取后展示整套实穿和 4 件单品，次数仍为 0 |
| 左侧模拟扫山门码 → 中央确认核验 | 现在用入口测试码演示到访。足迹、次数和这个地点关联的卡池同时更新。 | 入口 +2，云山可抽 |
| 去关联池 → 开启一次 → 穿上看看 → 保存 | 抽到什么就展示什么。这个部件进入衣橱，以后在其他池也会排除。 | 余额 1，回到云山后收集进度为 1 / 7 |
| 继续游玩 → 望山台核验 → 继续游玩 | 这里也关联云山池。游客自由游览，同一景区的次数可以留到后面用。 | +2，余额 3 |
| 山间手作铺到店核验 → 去做一枚旅行手作 → 模拟店员核验 | 商家的到店和完成体验分别记账，各自只发一次首次奖励。 | +1 后为 4，再 +2 为 6 |
| 去花溪池 → 抽取 → 保存搭配 | 在不同点位获得的次数，可以用在景区里另一个已解锁的池。 | 余额 5 |
| 如展示购买，选 10 次 → 继续模拟支付 → 成功 → 回到来源池 | 此处演示订单和到账。套餐测试价 7 元，本次没有实际扣款。 | +10 为 15；跳过购买则仍为 5 |
| 翻开旅行手账 → 制作纪念图 | 选择入口、到店、手作三条经历，取消望山台，填写标题。游客可以在途中制作，也可以回酒店再做。 | 4 条可选，实际选 3 条 |
| 生成预览 → 收进纪念册 → 保存 PNG → 打开图片 | 伙伴穿着刚保存的这一身，图片记录本次选中的地点与时间。这张图可以保存后分享。 | 实际本机 PNG；打开旧作品仍保留原版本 |

主讲控制在约 8—10 分钟，按观众反应决定是否展开购买支线。画面中的夜景、地图与角色服饰为演示素材。二维码只验证点位内容，定位和店员确认使用模拟结果。系统分享取决于设备能力，电脑上直接展示保存的 PNG 即可。

本轮[三栏彩排记录](../../output/stage-rehearsal/checks.json)：新手账走完 3 个地点、4 条经历、2 次抽取。未购买时余额为 5 次；加演 10 次模拟支付后为 15 次。视频选取山门、到店、手作三条经历，末帧展示的是本次导出的 PNG。另用独立手账复测了填错码、草稿保护、取消支付、刷新、备份还原、复位及跨标签切换身份。在三种桌面和三种手机窗口尺寸检查了中央底栏和侧栏操作；会场投影的亮度、字号和坐席距离仍需现场确认。

[见面礼领取与卡池进度实拍](../../output/visual-repair/见面礼与卡池进度.png)取自独立测试账号。进度按本池所有可获得奖品计算，已拥有的跨池共有奖品在各关联池都计入。

## 复验

先启动服务，运行 `npm --prefix design run check` 和 `npm --prefix design test`。浏览器验收需要 Chrome、Playwright 和相应的 FFmpeg 视频组件。将环境变量 `HXX_PLAYWRIGHT` 指向本机可用的 Playwright 包目录，或让 Node 直接解析该包，然后在仓库根目录执行：

```powershell
node design/demo/tests/run.mjs
node design/demo/tests/run.mjs --display
```

三栏专项运行 `node design/demo/tests/stage.mjs`；加 `--record` 会重新生成配套录像、截图及同次导出的 PNG 到 `output/stage-rehearsal/`。普通专项复测只写临时目录。

第一条运行独立浏览器的边界检查、四段彩排、备份恢复及图像验证。第二条打开真实 Chrome 窗口，按当前显示尺寸完成主线。正式验收输出在 `output/demo-rehearsal/`，备用存档和临时输出在已忽略的 `.codex/local-deploy/demo-run/`。再次执行会更新本机验收证据。备份及作品较多时需关注浏览器存储容量，写入失败时先保留现有手账并备份。

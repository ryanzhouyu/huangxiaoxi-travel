# 黄晓西客户演示

从仓库根目录启动 `./Start-Local.ps1`，先在[演示准备页](http://127.0.0.1:8765/design/demo/presenter.html)检查本机素材和存储，再打开[旅行手账](http://127.0.0.1:8765/design/demo/index.html)。Windows PowerShell 也可用 `.\Start-Local.ps1`。运行时只需要本地 HTTP 服务。

## 明早开场

提前在演示电脑打开准备页，确认显示“本机素材、存档读取和写入检查通过”。有需要保留的手账时先下载备份。需要从零开场时，点“重新开始彩排”并确认。用浏览器全屏，检查实际投影画面的文字、底部导航和明暗。将备用录屏和下载目录准备在本机。

| 现场操作 | 讲给客户听 | 核对点 |
| --- | --- | --- |
| 选新手账和初始搭配 | 这位是游客的数字伙伴黄晓西。游客用伙伴记录旅行，也能保留自己的真实形象隐私。 | 通用次数 0，尚无到访 |
| 游玩 → 黔山漫游 → 景区见面礼 → 试穿并保存 | 在线看景区就能收下这套装扮。试穿后由游客决定是否保存。 | 礼物 4 件，次数仍为 0 |
| 山门入口 → 扫码 → 填入此地点测试码 → 验证 | 现在用入口测试码演示到访。足迹、次数和这个地点关联的卡池同时更新。 | 入口 +2，云山可抽 |
| 去关联池 → 开启一次 → 穿上看看 → 保存 | 抽到什么就展示什么。这个部件进入衣橱，以后在其他池也会排除。 | 余额 1，回到云山 |
| 继续游玩 → 望山台核验 → 继续游玩 | 这里也关联云山池。游客自由游览，同一景区的次数可以留到后面用。 | +2，余额 3 |
| 山间手作铺到店核验 → 去做一枚旅行手作 → 模拟店员核验 | 商家的到店和完成体验分别记账，各自只发一次首次奖励。 | +1 后为 4，再 +2 为 6 |
| 去花溪池 → 抽取 → 保存搭配 | 在不同点位获得的次数，可以用在景区里另一个已解锁的池。 | 余额 5 |
| 如展示购买，选 10 次 → 继续模拟支付 → 成功 → 回到来源池 | 此处演示订单和到账。套餐测试价 7 元，本次没有实际扣款。 | +10 为 15；跳过购买则仍为 5 |
| 翻开旅行手账 → 制作纪念图 | 选择入口、到店、手作三条经历，取消望山台，填写标题。游客可以在途中制作，也可以回酒店再做。 | 4 条可选，实际选 3 条 |
| 生成预览 → 收进纪念册 → 保存 PNG → 打开图片 | 伙伴穿着刚保存的这一身，图片记录本次选中的地点与时间。这张图可以保存后分享。 | 实际本机 PNG；打开旧作品仍保留原版本 |

主讲控制在约 8—10 分钟，按观众反应决定是否展开购买支线。画面中的夜景、地图与角色服饰为演示素材。二维码只验证点位内容，定位和店员确认使用模拟结果。系统分享取决于设备能力，电脑上直接展示保存的 PNG 即可。

## 备用及复演

- [连续操作录屏](../../output/demo-rehearsal/连续操作彩排.webm)与[实际纪念图](../../output/demo-rehearsal/旅行纪念.png)可以离线播放／打开。录屏无声，包含新身份、回访及复位过程。
- 本机彩排生成的备用回访手账在 `.codex/local-deploy/demo-run/备用回访手账.json`。它通过正常点击和下载备份产生。准备页可载入备份，确认后替换当前客户演示手账。个人备份由演示者单独保存。
- 项目分支为 `codex/client-demo-20261106`。新电脑可运行 `git clone -b codex/client-demo-20261106 https://github.com/ryanzhouyu/huangxiaoxi-travel.git`。已有目录请先保护未提交工作，再 fetch、切到该分支并快进拉取。浏览器存档按来源域隔离。
- 旧原型及高保真评审稿分别在 `design/index.html`、`design/hifi/index.html`。[演示验收记录](../../docs/客户演示实施与彩排.md)列出本次复核范围及限制。

## 代码与存档

| 文件 | 使用方式 |
| --- | --- |
| `start.mjs`、`profile.mjs` | 加载本地素材并装配共享交互控制器。加载失败时可重试。 |
| `../app.mjs`、`../game-ui.mjs` | 复用导航守卫、事务、衣橱草稿、手账和动态场景构图。 |
| `../store.mjs`、`../data.mjs` | 使用原有点位、资产、卡池、套餐及领域用例。 |
| `views.mjs` | 根据当前身份和 ID 呈现核验、账号、收支及订单详情。 |
| `renderer.mjs` | 读取固定概念立绘，在浏览器分区渲染衣料、纹样、冠饰、鞋履以及静态表情／姿势。相同搭配复用缓存。 |
| `postcard.mjs` | 读取同一个渲染结果，按最后选中地点及背景搭配取景，结合经历和模板生成 PNG。 |
| `storage.mjs`、`presenter.mjs` | 业务进度映射到 `hxx.demo.v1`。草稿按演示批次和身份保存；复位／还原更新批次并通知其他标签。 |
| `style.css` | 演示页面材质、高清场景、投屏版式及小屏适配。 |
| `tests/` | 功能边界、主线复演、下载／还原和渲染检查。用独立上下文运行。 |

## 复验

先启动服务，运行 `npm --prefix design run check` 和 `npm --prefix design test`。浏览器验收需要 Chrome、Playwright 和相应的 FFmpeg 视频组件。将环境变量 `HXX_PLAYWRIGHT` 指向本机可用的 Playwright 包目录，或让 Node 直接解析该包，然后在仓库根目录执行：

```powershell
node design/demo/tests/run.mjs
node design/demo/tests/run.mjs --display
```

第一条运行独立浏览器的边界检查、四段彩排、备份恢复及图像验证。第二条打开真实 Chrome 窗口，按当前显示尺寸完成主线。正式验收输出在 `output/demo-rehearsal/`，备用存档和临时输出在已忽略的 `.codex/local-deploy/demo-run/`。再次执行会更新本机验收证据。备份及作品较多时需关注浏览器存储容量，写入失败时先保留现有手账并备份。
